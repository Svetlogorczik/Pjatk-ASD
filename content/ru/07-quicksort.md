## QuickSort — быстрая сортировка (Хоар, 1960)

QuickSort — один из самых используемых алгоритмов сортировки; для «случайных» данных его считают самым быстрым. Это ещё один пример принципа **«разделяй и властвуй»**, но работа распределена наоборот по сравнению с MergeSort:

- в MergeSort **разбиение тривиально** (пополам), а вся работа — **слияние**,
- в QuickSort вся работа — **разбиение** (partition), а «слияние» **пустое** — после сортировки обеих частей всё уже на месте.

**Идея:**

1. выбрать опорный элемент v (у нас — первый элемент фрагмента),
2. **разбить** фрагмент так, чтобы v встал на своё окончательное место j, слева были элементы ≤ v, справа ≥ v (это известная из темы 4 функция **partition**),
3. рекурсивно отсортировать левую часть `a[l..j−1]` и правую часть `a[j+1..r]`.

```pseudo title="QuickSort (лекция)"
void QuickSort(int l, int r, IntCiag a)
// сортируем a.ciag[l..r], l < r
{
  int j;
  j := partition(l, r);
  if j - 1 > l then QuickSort(l, j - 1, a);
  if r > j + 1 then QuickSort(j + 1, r, a);
}
```

:::def
**Корректность** QuickSort основана на том, что после `partition(l, r)`:
1. элемент v = a[j] стоит на своём **окончательном** месте,
2. a[l..j−1] ≤ v,
3. v ≤ a[j+1..r].

Значит, достаточно (рекурсивно) отсортировать обе части независимо — между ними уже ничего переносить не нужно.
:::

**Пример** для `[9, 4, 7, 1, 8, 2, 6]` (в скобках — опорный на своём месте):

```text title="Последовательные вызовы"
QS(0,6): опорный 9 → поз. 6   [6, 4, 7, 1, 8, 2, (9)]
  QS(0,5): опорный 6 → поз. 3 [1, 4, 2, (6), 8, 7, 9]
    QS(0,2): опорный 1 → поз. 0 [(1), 4, 2, 6, 8, 7, 9]
      QS(1,2): опорный 4 → поз. 2 [1, 2, (4), 6, 8, 7, 9]
    QS(4,5): опорный 8 → поз. 5 [1, 2, 4, 6, 7, (8), 9]
результат: [1, 2, 4, 6, 7, 8, 9]
```

### Анализ QuickSort

Результат анализа с лекции:

- **W(n) = ½n² + O(n)** — когда опорный всегда крайний (например, данные **уже отсортированы**!), разбиение максимально неравное (0 и n − 1),
- **Δ(n) = O(n²)**,
- **A(n) ≈ 1,4 · n log₂ n + O(n)** — в среднем всего на ~40% больше сравнений, чем оптимальные n log₂ n,
- **δ(n) ≈ 0,65 n** (отклонение мало по сравнению с n log n — алгоритм обычно работает близко к среднему).

:::warn
Парадокс QuickSort: для версии «опорный = первый элемент» худший случай — **уже отсортированные** данные (или отсортированные наоборот): тогда время квадратичное, а глубина рекурсии равна n.
:::

### Как избежать худшего случая? {own}

:::own
Эти улучшения на слайдах не разбирались — это стандартные практические приёмы, добавленные автором сайта.
:::

- **Случайный опорный** — перед partition поменять a[l] со случайным элементом фрагмента. Тогда никакие конкретные данные не «вредные»; ожидаемое время O(n log n) для любых данных.
- **Медиана трёх** — опорный = медиана из a[l], a[середина], a[r]. Защищает от отсортированных данных.
- **Маленькие фрагменты** (например, < 10 элементов) сортировать InsertionSort — для них он быстрее.

## Другие способы разбиения: Split и «польский флаг»

Функция partition с лекции использует два указателя, идущих навстречу. На занятиях её сравнивают с другим разбиением — **Split**.

:::info
Процедура **Split** встречается в задачах занятий, но её нет на слайдах лекций. Ниже — версия из польских учебников (однонаправленная, опорный = первый элемент). Если преподаватель дал другую версию — придерживайтесь его определения.
:::

**Split(l, r):** v = a[l]; указатель s отмечает конец зоны «меньше v». Идём i от l+1 до r: если a[i] < v, сдвигаем s на 1 и меняем a[s] с a[i]. В конце меняем a[l] с a[s] — опорный встаёт на позицию s.

```pseudo title="Split"
Split(a, l, r):
{
  v := a[l];  s := l;
  for i := l+1 to r do
    if a[i] < v then {
      s := s + 1;
      обмен(a[s], a[i])
    }
  обмен(a[l], a[s]);
  return s
}
```

Лекция «Dziel i rządź» называет разбиение алгоритмом **«польского флага»**: «белые» элементы (≤ A[l]) должны оказаться слева, «красные» (≥ A[l]) — справа, как два цвета флага (сравните задачу про робота и шары в теме 2). Он работает как partition: i идёт вправо от `l + 1` по элементам ≤ A[l], j идёт влево от `p` по элементам ≥ A[l], а элементы «не на своей стороне» меняются местами. В конце `Zamien(l, j)` (обмен) ставит опорный элемент на место j.

:::warn Замечание от автора сайта
В своей реализации следите за границами: цикл «идти влево, пока A[j] ≥ A[l]» должен остановиться не позже позиции l (сам A[l] удовлетворяет равенству!). Версия partition с лекции asd5 (с `i <= r` и строгими неравенствами) в этом смысле безопасна.
:::

Все три версии делают одно и то же (разбивают относительно опорного за линейное время) — отличаются числом обменов и тем, куда попадают элементы, равные v.

## QuickSort без рекурсии — стек

Лекция asd6 спрашивает: что на самом деле происходит при рекурсивных вызовах? Каждый вызов `QuickSort(l, r)` имеет локальные копии `l, r, i, j, v, x`, которые надо хранить до возврата. К счастью, в QuickSort:

1. оба рекурсивных вызова **независимы** — их можно выполнять в любом порядке,
2. они в **конце** функции — поэтому один из них можно заменить **циклом**, а параметры другого сохранить в **стеке**.

В стеке храним пары индексов [l, r] подпоследовательностей, которые ещё нужно отсортировать. **В стек кладём более длинную часть, а короткой занимаемся сразу.** Тогда каждая следующая часть в стеке как минимум вдвое короче предыдущей, и в стеке одновременно не более ~log₂ n пар:

- **S(n) = O(log n)** дополнительной памяти.

Итеративная версия — в коде выше (`quickSortIterative`).

:::def
**Стек** (stack) — абстрактная структура данных с операциями: `push(x)` — положить x наверх, `pop()` — снять и вернуть последний положенный элемент, `top()` — посмотреть его, не снимая, `size()`, `isEmpty()`. Правило: **последним пришёл — первым ушёл** (LIFO). Подробности в теме 9.
:::

## Можно ли сортировать быстрее n log n? Деревья решений

Любой алгоритм сортировки **сравнениями** (SelectionSort, InsertionSort, MergeSort, QuickSort, …) можно нарисовать как **дерево решений**:

:::def
**Дерево решений** для последовательности из n элементов: во внутренних узлах — сравнения «aᵢ : aⱼ?», у каждого сравнения два исхода (левый и правый сын), а в **листьях** — результаты, отсортированные перестановки. Выполнение алгоритма на конкретных данных — это **путь от корня к листу**; число сравнений = длина этого пути.
:::

Дерево решений для n = 3 (элементы a, b, c):

```tree caption="Дерево решений для сортировки 3 элементов: в узле «a:b» спрашиваем, верно ли a ≤ b (влево = да)."
a:b(b:c(abc,a:c(acb,cab)),a:c(bac,b:c(bca,cba)))
```

Рассуждение с лекции:

1. у дерева должно быть не меньше **n!** листьев (каждой из n! перестановок данных нужен свой ответ),
2. у двоичного дерева высоты h не более **2ʰ** листьев,
3. значит 2ʰ ≥ n!, то есть **h ≥ log₂(n!)**.

А log₂(n!) = Θ(n log n) (по формуле Стирлинга: log₂ n! ≈ n log₂ n − 1,44 n).

:::def
**Теорема:** любой алгоритм сортировки сравнениями в худшем случае делает не менее **⌈log₂ n!⌉ = Ω(n log n)** сравнений. И **в среднем** тоже нужно не менее log₂ n! сравнений.
:::

Вывод: **MergeSort и HeapSort асимптотически оптимальны**, а QuickSort — в среднем.

## Сортировка за линейное время — без сравнений

Теорема про n log n касается только алгоритмов, которые **сравнивают** элементы. Если мы знаем о данных больше (например, что это небольшие целые числа), можно их **не сравнивать** — и опуститься до линейного времени!

### CountingSort — сортировка подсчётом

Пусть сортируем целые числа из диапазона **0…m−1**. Для каждого значения j считаем, сколько раз оно встречается (`count[j]`). Затем префиксные суммы говорят, **сколько элементов ≤ j** — то есть где кончается место для значения j в результате.

```pseudo title="CountSort (лекция, кратко)"
for j := 0 to m-1 do count[j] := 0;
for i := 0 to n-1 do count[a[i]]++;             // count[j] = число вхождений j
for j := 1 to m-1 do count[j] += count[j-1];    // count[j] = число элементов <= j
for i := n-1 downto 0 do {                       // с конца → устойчиво
  p := a[i];
  count[p]--;
  t[count[p]] := p;
}
for i := 0 to n-1 do a[i] := t[i];
```

**Пример** для `[3, 1, 4, 1, 5, 2, 6, 5, 3]` (m = 7):

| значение j | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| count (вхождения) | 0 | 2 | 1 | 2 | 1 | 2 | 1 |
| count (суммы ≤ j) | 0 | 2 | 3 | 5 | 6 | 8 | 9 |

Результат: `[1, 1, 2, 3, 3, 4, 5, 5, 6]`.

Анализ с лекции:

- **W(n, m) = A(n, m) = O(n + m)**, Δ = δ = 0,
- **S(n, m) = n + m + O(1)** (массив результата t и массив count),
- достоинства: **скорость**, когда m = O(n); алгоритм **устойчив** (для устойчивости важен проход от a[n−1] к a[0]),
- недостаток: дополнительная память; подходит только для **небольших m**.

### RadixSort — поразрядная сортировка

Для больших m делим ключи на части (цифры или группы битов) и сортируем **устойчивым** CountingSort **сначала по последней (младшей) цифре**, потом по предпоследней, …, в конце по первой. Устойчивость критична: если старшие цифры равны, порядок решают младшие — а они уже правильно расставлены на предыдущих проходах.

- для n чисел из d цифр в системе с основанием k: **O(d · (n + k))**.

### BucketSort — карманная (блочная) сортировка

Со слайдов 2009: если числа **равномерно распределены** на [0, 1), делим отрезок на n равных **корзин**, бросаем каждое число в его корзину (корзина ⌊n·x⌋), сортируем корзины (они маленькие — в среднем по 1 элементу) и склеиваем. **В среднем O(n)**, в худшем — сколько стоит сортировка одной полной корзины.

:::def Устойчивость (stabilność)
Алгоритм сортировки **устойчив** ⇔ сохраняет исходный относительный порядок элементов с одинаковым значением. Например, 4, 2ₐ, 3, 1, 2_b, 5, 2_c → 1, 2ₐ, 2_b, 2_c, 3, 4, 5. Полезно при сортировке многоатрибутных записей по нескольким атрибутам по очереди (например, возраст, зарплата) — сортировка по следующему атрибуту не разрушает результат предыдущей.
:::

**QuickSort** (C.A.R. Hoare, «разделяй и властвуй»): partition выбирает **ось (pivot)** — в этой лекции **первый** элемент — и переставляет элементы так, что слева не большие, справа не меньшие; возвращает индекс оси. Пример: 5,2,1,7,2,6,1,3,4,8,6,0 → 3,2,1,0,2,4,1,**5**,6,8,6,7 (возвращает 7). Затем рекурсивно сортируем части слева и справа от оси (если ось оказалась на краю, одна часть пуста).

```pseudo
partition(a, l, r){

  i = l + 1;
  j = r;
  p = a[l]; //"pivot"
  temp;

  do{
    while((i < r) && (a[i] <= p)) i++;
    while((j > i) && (a[j] >= p)) j--;
    if(i < j) {temp = a[i]; a[i] = a[j]; a[j] = temp;}
  }while(i < j);
  // when (i==r):
  if(a[i] > p) {a[l] = a[i - 1]; a[i - 1] = p; return i - 1;}
  else {a[l] = a[i]; a[i] = p; return i;}
}

quicksort(a, l, r){

    if(l >= r) return;
    k = partition(a, l, r);
    quicksort(a, l, k - 1);
    quicksort(a, k + 1, r);
}
```

**Анализ partition:** индекс i идёт вправо, пока не встретит число больше p, j — влево, пока не встретит меньшее; тогда они меняются; в конце p меняется с последним элементом «левой» части. Сравнение выполняется один раз для каждой позиции индекса — всего столько, сколько элементов минус один: $W(n)=A(n)=\Theta(n)$, $S(n)=O(1)$ (работает **на месте**).

**Анализ QuickSort:** на каждом уровне рекурсии всего Θ(n) сравнений, поэтому всё зависит от **глубины рекурсии**. Ось всегда посередине → глубина Θ(log n) → **Θ(n log n)**. Ось всегда на краю (например, последовательность **отсортирована или отсортирована обратно**) → последовательность короче лишь на 1, глубина Θ(n) → $W(n)=\Theta(n^2)$. В среднем (все перестановки равновероятны) глубина Θ(log n): $A(n)=\Theta(n\log n)$ с константой около **1,44** — QuickSort в среднем быстрее MergeSort. Базовая версия **не устойчива**; существуют улучшения (гарантированные n log n, устойчивость).

**Нижняя граница.** Сортировка сравнениями — это **дерево решений**: каждый узел — сравнение «a < b?», листья — все **n!** перестановок. Высота двоичного дерева с n! листьями не меньше $\log_2(n!)=\Theta(n\log n)$ — не существует сортировки сравнениями с меньшим порядком **средней и пессимистической** сложности, чем Θ(n log n). Быстрее можно только **без сравнений** — ценой памяти («**время против памяти**»).

**CountSort** (прямая адресация, данные в RAM). Элементы — **натуральные** числа. Вспомогательные массивы: **counts** (длина = максимум + 1) и **result**. Три фазы: (1) подсчёт вхождений, (2) накопительное суммирование слева направо (сколько элементов не больше данного), (3) повторный проход по входу и отправка каждого элемента в result по адресу из counts (счётчик уменьшается перед использованием); **для устойчивости вход проходим «с конца»**.

```pseudo
countSort(a, l){

    max = maxValue(a, l);
    l1 = max + 1;
    counts[l1];
    result[l];
    for(i = 0; i < l1; i++) counts[i] = 0;

    for(i = 0; i < l; i++) counts[a[i]]++;
    for(i = 1; i < l1; i++) counts[i] += counts[i - 1];
    for(i = l - 1; i >= 0; i--)
       result[--counts[a[i]]] = a[i];
}
```

Пример со слайдов: (3,2,5,1,2,6,8,1,2,4), max = 8 → counts после фазы 1: 0,2,3,1,1,1,1,0,1; после фазы 2: 0,2,5,6,7,8,9,9,10. **Анализ:** доминирующая операция — присваивание значения в массиве; размер данных: n (длина) и **m (максимальное значение)**; $A(n,m)=W(n,m)=2n+2m=\Theta(n+m)$ — линейная; $S(n,m)=n+m=\Theta(n+m)$. Плохой выбор, когда m ≫ n (например, последовательность (10⁹, 1) — миллиард шагов и массив длины 10⁹).

**RadixSort** — схема сортировки многоэлементных объектов фиксированной длины (строки, многозначные числа) с помощью вспомогательного **устойчивого** алгоритма: сначала по **последней** позиции, затем по предпоследней, … до первой. Для маленького алфавита (цифры 0–9, буквы) хороший вспомогательный алгоритм — CountSort. Пример: (212, 305, 115, 202, 131) → по последней: (131, 212, 202, 305, 115) → по средней: (202, 305, 212, 115, 131) → по первой: (115, 131, 202, 212, 305).

### Примерные вопросы со слайдов

- Определение устойчивости и зачем она нужна; для каждого из 5 алгоритмов — устойчив ли он и **какое место в коде** это решает.
- Спецификация partition и её результат на данном массиве; анализ (время, память). Псевдокод QuickSort, анализ, улучшения.
- Нижняя граница сортировки сравнениями.
- CountSort на данной последовательности — итоговое содержимое counts; анализ. Попарное сравнение 5 алгоритмов сортировки.
- Расширение CountSort на целые числа (в том числе отрицательные). RadixSort на 3-значных числах; сложность для d-значных чисел (ответ автора сайта: d проходов CountSort, то есть Θ(d·(n + 10))).

=== summary ===

:::exam Что нужно уметь
Задача 3: **partition** — возвращённый индекс, первый элемент, число swap (с последним). Задача 4: **CountSort** — массив `counts` после 3 фаз. RadixSort, устойчивость, нижняя граница.
:::

## partition (опорный = первый элемент)

1. `i` идёт вправо, пока `a[i] <= p`; `j` — влево, пока `a[j] >= p`.
2. Если `i < j` — меняем `a[i]`, `a[j]` и повторяем.
3. Конец: опорный встаёт на позицию `i-1` (если `a[i] > p`) или `i` — это **последний swap**.

:::tip Быстрая проверка
Возвращённый индекс = число элементов **меньше** опорного (при различных элементах). Swap = обмены пар + 1.
:::

## CountSort (натуральные числа 0..max)

| Фаза | что делает | `counts` после фазы |
|---|---|---|
| 1. подсчёт | `counts[a[i]]++` | частоты |
| 2. суммирование | `counts[i] += counts[i-1]` | префиксные суммы (последняя = $n$) |
| 3. запись (с **конца**) | `result[--counts[a[i]]] = a[i]` | b), сдвинутое вправо, с 0 в начале |

**RadixSort:** устойчиво сортируем по **последней** цифре, затем по предпоследней … по первой (вспомогательный — CountSort).

## Сложности

| | W | A | S | устойчив |
|---|---|---|---|---|
| partition | $\Theta(n)$ | $\Theta(n)$ | $O(1)$ | — |
| QuickSort | $\Theta(n^2)$ (отсортированные) | $\Theta(n\log n)$ (≈1,44) | на месте | нет |
| CountSort | $\Theta(n+m)$ | $\Theta(n+m)$ | $\Theta(n+m)$ | да (фаза 3 с конца) |
| RadixSort ($d$ цифр) | $\Theta(d(n+10))$ | | | да |

:::formula Нижняя граница сортировки сравнениями
$$\log_2(n!)=\Theta(n\log n)$$
У дерева решений $n!$ листьев. Быстрее — только **без сравнений** (CountSort), ценой памяти.
:::

:::warn Типичные ошибки
- забыт **последний** swap в partition,
- фаза 3 CountSort с начала (теряется устойчивость),
- `counts` от 0 до **max** — включая значения, которых нет (запись 0).
:::

:::task level=2 source="own" title="Худший случай QuickSort"
Сколько сравнений элементов сделает QuickSort с лекции на **уже отсортированных** данных `[1, 2, 3, 4, 5, 6, 7, 8]`? Какой будет глубина рекурсии? Что изменил бы случайный выбор опорного?
::hint
Для отсортированного фрагмента длины m опорный — наименьший: указатель i останавливается сразу, а j проходит весь фрагмент.
::solution
Для фрагмента длины m partition делает **m + 1** сравнений (1 со стороны i, m со стороны j), а опорный остаётся в начале — следующий фрагмент имеет длину m − 1. Всего для m = 8, 7, …, 2:

9 + 8 + 7 + 6 + 5 + 4 + 3 = **42 сравнения**, глубина рекурсии **7** (= n − 1). Это и есть W(n) = ½n² + O(n).

Со случайным опорным отсортированные данные перестают быть «вредными»: ожидаемое число сравнений ≈ 1,4 n log₂ n, ожидаемая глубина рекурсии — O(log n).
:::

:::task level=1 source="own" title="Дерево решений"
Сколько листьев должно быть у дерева решений любого алгоритма сортировки сравнениями для **n = 4** элементов? Какова минимально возможная высота этого дерева (то есть минимальное пессимистическое число сравнений)? А для n = 5?
::hint
Число листьев ≥ n!, а у двоичного дерева высоты h не более 2ʰ листьев.
::solution
- n = 4: не менее **4! = 24** листьев; 2ʰ ≥ 24 ⇒ h ≥ ⌈log₂ 24⌉ = **5** сравнений.
- n = 5: **120** листьев; ⌈log₂ 120⌉ = **7** сравнений.

(Для n = 5 существует алгоритм, который действительно сортирует за 7 сравнений — граница достижима.)
:::
