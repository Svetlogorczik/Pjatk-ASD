## Зачем измерять сложность?

Мы хотим сравнивать алгоритмы **независимо от компьютера**, языка программирования и опыта программиста. Поэтому меряем не секунды, а **количество операций**, которые выполнит алгоритм.

:::def
**Вычислительная сложность** (*złożoność obliczeniowa*) алгоритма — это количество компьютерных ресурсов, нужных для его выполнения. Два основных ресурса — **время** (временная сложность) и **память** (сложность по памяти — дополнительная память сверх входных данных).
:::

### Размер данных

Сложность выражаем как функцию **размера данных n**. Что считать размером — зависит от задачи:

| Задача | Размер данных |
|---|---|
| сортировка, поиск в массиве | количество элементов |
| обход дерева | количество узлов |
| вычисления с числами | **количество цифр** (битов), а не само значение! |
| вычисление значения многочлена | степень многочлена |
| графы | число вершин и рёбер |

### Доминирующая операция

Мы не считаем все операции — это скучно и зависит от деталей. Выбираем **доминирующую операцию** (*operacja dominująca*): такую, что общее число всех операций **пропорционально** числу её выполнений.

- сортировка → **сравнение** двух элементов (иногда ещё обмен),
- обход дерева → переход по ребру,
- вычисления с многочленами → арифметические операции +, −, ·, /.

**Единица сложности** — одно выполнение доминирующей операции.

## Пессимистическая и ожидаемая сложность

Один и тот же алгоритм на разных данных одного размера может работать разное время (например, искомый элемент в начале или в конце). Отсюда две меры:

:::def
Обозначения: **Dₙ** — множество всех наборов данных размера n; **t(d)** — число доминирующих операций для набора d; **Xₙ** — случайная величина со значениями t(d); **pₙₖ** — вероятность того, что алгоритм выполнит k доминирующих операций.

- **Пессимистическая** (*pesymistyczna*) временная сложность: **W(n) = sup { t(d) : d ∈ Dₙ }** — «худший случай».
- **Ожидаемая** (средняя, *oczekiwana*) временная сложность: **A(n) = Σ k · pₙₖ** — математическое ожидание Xₙ, «типичный случай».
:::

Говорят ещё о **чувствительности** (*wrażliwość*) алгоритма — насколько его время «скачет» в зависимости от данных:

- **пессимистическая чувствительность:** Δ(n) = sup { t(d₁) − t(d₂) : d₁, d₂ ∈ Dₙ } (разница между худшим и лучшим),
- **ожидаемая чувствительность:** δ(n) = dev(Xₙ) — стандартное отклонение Xₙ.

Чем больше Δ и δ, тем **менее предсказуем** алгоритм.

:::analogy
Дорога в университет: W(n) — время в самый плохой день (пробка, сломался трамвай), A(n) — среднее время за много дней, а чувствительность говорит, насколько эти времена различаются. Перед важным тестом вы планируете по W(n); считая, сколько времени в месяц проводите в дороге, — по A(n).
:::

### Пример с лекции: последовательный поиск

Ищем `a` в массиве `L[0..N−1]`. Хитрость: в конец массива кладём **сторожа** (*strażnik*) `L[N] := a`, поэтому цикл точно остановится и не нужно проверять конец массива.

```pseudo title="Последовательный поиск со сторожем"
Algorytm Szukaj(L, N, a):
  Dane:  N ≥ 0, a - искомый элемент, L[0..N] (ячейка L[N] свободна)
  Wynik: i, такое что L[i] = a (0 ≤ i ≤ N-1), или N, если a нет в L
{
  L[N] := a;  i := 0;
  while L[i] <> a do
    i := i + 1;
  return i
}
```

- размер данных: n = N,
- доминирующая операция: сравнение `L[i] ≠ a`,
- **W(n) = n + 1** (a нет в массиве — доходим до сторожа),
- **Δ(n) = n** (в лучшем случае 1 сравнение, в худшем n + 1),
- **A(n) = (n + 1)/2** (если a есть в массиве и все позиции равновероятны),
- **δ(n) ≈ 0,29 n**.

## Асимптотическая нотация: O, Ω, Θ

Точные формулы (например, W(n) = 3n² + 7n + 12) неудобны. Нас интересует **порядок величины**, то есть поведение при очень больших n. Константы и слагаемые младших порядков отбрасываем.

:::def
Пусть f, g : ℕ → ℝ₊ ∪ {0}.
- **f(n) = O(g(n))** («f не более чем порядка g»), если существуют константы **c > 0** и **n₀** такие, что **f(n) ≤ c · g(n)** для всех n > n₀.
- **f(n) = Ω(g(n))** («f не менее чем порядка g»), если g(n) = O(f(n)).
- **f(n) = Θ(g(n))** («f ровно порядка g»), если f = O(g) и f = Ω(g).
:::

Пример с лекции: **n² + 2n = O(n²)**, так как n² + 2n ≤ 3n² при всех n ≥ 1 (c = 3, n₀ = 1).

:::analogy
O(g) — это «потолок», Ω(g) — «пол», а Θ(g) — «точный размер». Говоря «алгоритм O(n²)», мы обещаем, что он не хуже квадратичного (но может быть лучше). Говоря «Θ(n²)» — что он ровно квадратичный.
:::

:::warn
«f = O(g)» — **не** равенство в обычном смысле. Из n = O(n²) и n² = O(n²) не следует n = n². Читайте знак «=» как «принадлежит классу».
:::

### Самые частые классы сложности

| Порядок | Название | Пример |
|---|---|---|
| 1 | константная | доступ к `A[i]` |
| log n | логарифмическая | бинарный поиск |
| n | линейная | последовательный поиск, максимум |
| n log n | линейно-логарифмическая | MergeSort, HeapSort |
| n² | квадратичная | SelectionSort, InsertionSort |
| n³, n⁴, … | полиномиальная | «школьное» умножение матриц (n³) |
| n^(log n) | субэкспоненциальная | |
| 2ⁿ | экспоненциальная | перебор всех подмножеств |
| n! | факториальная | перебор всех перестановок |

Порядок: **1 ≺ log n ≺ √n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ n^(log n) ≺ 2ⁿ ≺ n!**

### Полезные правила {own}

:::own
Эти правила прямо следуют из определения, но на слайдах не выписаны — их собрал автор сайта, потому что они нужны в задачах.
:::

- **Константы не важны:** 100·n² = Θ(n²), n/1000 = Θ(n).
- **Важно самое быстрорастущее слагаемое:** 3n³ + 50n² + 7 = Θ(n³).
- **Основание логарифма не важно:** log₂ n = Θ(log₁₀ n), они отличаются постоянным множителем (log₂ n = log₁₀ n / log₁₀ 2).
- **Любой многочлен проигрывает экспоненте:** n¹⁰⁰ = O(1,01ⁿ). **Любая степень логарифма проигрывает степени n:** (log n)¹⁰ = O(√n).
- **Формула Стирлинга:** n! ≈ √(2πn)·(n/e)ⁿ, поэтому **log(n!) = Θ(n log n)** (пригодится для нижней оценки сортировки).

### Сложность составных программ {own}

:::own
Быстрые правила подсчёта сложности кода (добавлены автором; нужны, например, в задаче 5 с занятий).
:::

- **Инструкции подряд:** сложности **складываются** → побеждает наибольшая. Θ(n) + Θ(n²) = Θ(n²).
- **Цикл, выполняемый k раз:** сложность тела **умножаем на k**. Цикл n раз с телом Θ(log n) → Θ(n log n).
- **Вложенные циклы:** перемножаем числа итераций. `for i < n { for j < n {…} }` → n · n = n².
- **Цикл, где счётчик делится** (`i := i div 2`) → log n итераций.
- **Ожидание суммы = сумма ожиданий**, поэтому средние сложности последовательных вызовов просто складываются.
- Если какая-то часть известна только **снизу** (Ω), то и всё целое известно только снизу.

## Почему экспоненциальные алгоритмы бесполезны

Таблица с лекции: время работы алгоритма, выполняющего **2ⁿ** операций, на компьютере, делающем 10⁶ или 10⁹ операций в секунду.

| Размер n | 20 | 50 | 100 | 200 |
|---|---|---|---|---|
| 10⁶ операций/с | 1,04 с | 35,7 лет | 4·10¹⁴ веков | 5·10⁴⁴ веков |
| 10⁹ операций/с | 0,001 с | 13 дней | 4·10¹¹ веков | 5·10⁴¹ веков |

Даже **1000-кратное** ускорение компьютера ничего не даёт: для n = 100 вместо 4·10¹⁴ веков ждём «всего» 4·10¹¹ веков.

:::def
Алгоритм называют **непрактичным** (нереализуемым), если его сложность экспоненциальна относительно размера данных. На больших данных такой алгоритм применить нельзя — независимо от мощности компьютера.
:::

### Быстрее компьютер — больше данные? {own}

:::own
Расчёт «как быстрый компьютер влияет на размер данных» — типичная задача на занятиях, а в лекции есть только таблица-намёк. Ниже — метод по шагам.
:::

Считаем, что время = c · f(n), где c — время одной «единицы». Если для данных размера x время равно t, то **c = t / f(x)**. Дальше:

- **время для другого размера y:** c · f(y),
- **максимальный размер за время t':** наибольшее n, при котором c · f(n) ≤ t',
- **компьютер в p раз быстрее:** время делим на p.

| f(n) | Компьютер в 1000 раз быстрее позволяет увеличить n… |
|---|---|
| n | в 1000 раз |
| n² | примерно в 31,6 раза (√1000) |
| n³ | в 10 раз (∛1000) |
| 2ⁿ | всего примерно на **10** (так как 2¹⁰ ≈ 1000) |

## Снова корень: размер данных — это число цифр

Вернёмся к двум алгоритмам ⌊√n⌋ из темы 2. Доминирующей операцией возьмём сравнение в условии цикла.

- **Линейная версия:** W(n) = √n, Δ(n) = 0, A(n) = √n, δ(n) = 0.
- **Бинарная версия:** около log₂ n итераций.

Но внимание: для чисел **размер данных — это количество цифр** d ≈ log n, а не само значение n! Тогда:

- линейная версия: **W(d) = 2^(d/2)** — **экспоненциальная** сложность!
- бинарная версия: **W(d) = d** — **линейная** сложность.

Для больших чисел (например, 100-значных) разница колоссальная.

:::exam
Вопрос «какова сложность алгоритма на числах?» — всегда уточняйте, речь о сложности **относительно значения** n или **относительно размера данных** (числа цифр/битов). Алгоритм, который выглядит «линейным» (n итераций), экспоненциален относительно числа битов.
:::

## Когда сложность — не всё

Лекция напоминает об ограничениях такого анализа:

1. алгоритм и его реализация (программа) записаны на разных языках — константы могут отличаться,
2. чувствительность к данным может привести к тому, что на **наших** данных программа ведёт себя иначе, чем говорят W(n) и A(n),
3. реальное распределение данных (Xₙ) трудно предсказать,
4. для некоторых алгоритмов точные оценки A(n) неизвестны,
5. иногда один алгоритм лучше на одних данных, а другой — на других.

Важное свойство — **простота** алгоритма. Более простой алгоритм стоит выбрать, если программа будет запускаться **лишь несколько раз** или только на **малых данных**.


## Версия лекции 2026/2027 (M. Sydow) — определения для тестов

:::exam
На тестах 2026/2027 действуют формулировки M. Sydow. Главные отличия от текста выше: обозначения **W(n)**, **A(n)**, **S(n)** (без «чувствительности» Δ, δ), **пять** вариантов асимптотической нотации (также **o** и **ω**) и альтернативное определение через **предел отношения**. Анализ сложности без указания **доминирующей операции** и **размера данных** неполон.
:::

Хороший алгоритм обладает двумя свойствами: возвращает **правильный результат** (полная корректность — [тема 2](topic:t02)) и **эффективен** — достигает результата при минимальных затратах ресурсов: объёма работы (времени) и памяти. Меньшая сложность = более эффективный алгоритм. Мера скорости должна быть **независимой от языка/платформы** и по возможности **независимой от данных** — поэтому мы **считаем базовые операции**.

:::def Доминирующие операции (operacje dominujące)
Множество **доминирующих операций** — это множество таких операций, число которых **пропорционально числу всех операций**, выполненных всем алгоритмом. Доминирующей **не** является, например, операция, выполняемая один раз; зато **каждый цикл** или ветвь условной инструкции должны содержать доминирующую операцию.
:::

Пример со слайдов — `find(arr, len, key)` (возвращает индекс ключа или −1):

```pseudo
find(arr, len, key){
  i = 0
  while(i < len){
    if(arr[i] == key)
      return i
    i++
  }
  return -1
}
```

| Кандидат | Доминирующая? |
|---|---|
| присваивание `i = 0` | нет (выполняется один раз) |
| сравнение `i < len` | да |
| сравнение `arr[i] == key` | да |
| обе вместе | да (хотя это не обязательно) |
| `return i` | нет (не более одного раза) |
| `i++` | да |

**Два обязательных шага перед анализом сложности:** (1) определить множество **доминирующих операций**, (2) определить функцию аргументов, которая является **размером входных данных**. В `find` размер данных — **длина массива** (len = n).

:::def Временная и пространственная сложность
- **Временная сложность** — число доминирующих операций, которые выполнит алгоритм, **как функция размера данных**.
- **Пессимистическая временная сложность:** **W(n) = sup { t(d) : d ∈ Dₙ }**, где Dₙ — множество всех данных размера n, t(d) — число доминирующих операций на данных d (W — *worst*).
- **Средняя временная сложность:** **A(n) = Σ_{k≥0} pₙₖ · k = Σ P(Xₙ = k) · k = E(Xₙ)** — математическое ожидание случайной величины Xₙ (числа доминирующих операций на случайных данных размера n); требует предположить **модель случайности данных** (распределение pₙₖ) (A — *average*).
- **Пространственная сложность S(n)** — число единиц памяти, используемых алгоритмом, как функция размера данных; аналогично пессимистическая **SW(n)** и средняя **SA(n)**. Если память не зависит от данных: **S(n) = const = O(1)**.
:::

Для `find` число сравнений `arr[i] == key` — от 1 (ключ в начале — «оптимистичный» случай) до n (в конце или нет совсем — «пессимистичный»), поэтому **W(n) = n**. Если ключ с равной вероятностью 1/n находится на любой позиции (k-я позиция → k сравнений): **A(n) = Σ_{k=1..n} (1/n)·k = (n+1)/2** — «в среднем посередине массива». Память: **SA(n) = O(1)**.

### Пять вариантов асимптотической нотации

Нас интересует **характер скорости роста**, а не конкретная функция: например, в A(n) = 3,45·n + 2 несущественно слагаемое «+2», а если важно лишь то, что функция **линейная**, — то и константа 3,45.

| Нотация | Аналог | Смысл |
|---|---|---|
| f = **Θ(g)** | = | одинаковый порядок: f = O(g) ∧ g = O(f) |
| f = **O(g)** («O большое») | ≤ | **нестрогая** верхняя оценка |
| f = **Ω(g)** («омега большое») | ≥ | **нестрогая** нижняя оценка |
| f = **o(g)** («o малое») | < | **строгая** верхняя оценка |
| f = **ω(g)** («омега малое») | > | **строгая** нижняя оценка |

Заглавные буквы — оценки «с равенством» (нестрогие), строчные — строгие. Аналогия с числами неполная: числа упорядочены линейно, а порядки функций — нет.

:::def Определения
- **f(n) = O(g(n)) ⇔ ∃ c>0 ∃ n₀ ∀ n≥n₀: f(n) ≤ c·g(n)** — g является верхней оценкой порядка f.
- **f(n) = Θ(g(n)) ⇔ f(n) = O(g(n)) ∧ g(n) = O(f(n))** — одинаковый порядок величины.
- f(n) = Ω(g(n)) ⇔ ∃ c>0 ∃ n₀ ∀ n≥n₀: f(n) ≥ c·g(n) (равносильно g = O(f)).
- f(n) = o(g(n)) ⇔ ∀ c>0 ∃ n₀ ∀ n≥n₀: f(n) ≤ c·g(n) (для **любой** константы, а не для какой-то).
- f(n) = ω(g(n)) ⇔ ∀ c>0 ∃ n₀ ∀ n≥n₀: f(n) ≥ c·g(n).
:::

:::own
Слайды дают кванторные определения O и Θ и смысл остальных символов; определения Ω, o, ω в той же форме дописал автор сайта (стандартные, как в учебнике Кормена).
:::

**Определение через предел** (равносильное; f, g положительны): вычислите lim_{n→∞} f(n)/g(n). Если предел существует, то:
- **∞** → у f **более высокий** порядок: f = ω(g),
- **положительная константа** → порядки **равны**: f = Θ(g),
- **0** → у f **более низкий** порядок: f = o(g).

**Примеры со слайдов:** A(n) = (n+1)/2 = O(n); SA(n) = O(1); f(n) = 3n² + 2n − 7 **не** является O(n), но является O(n²) и также O(n³) (менее точная оценка); n² + n − 3 = Θ(n²) — достаточно смотреть на **доминирующее** слагаемое. W(n) = o(n) означает: «порядок пессимистической сложности существенно меньше линейного».

:::warn Замечания о записи
Знак «=» в f(n) = O(g(n)) **не** означает обычного равенства — это лишь вид записи. Нельзя, например, вычитать из обеих частей, а нотацию используют в основном **справа** от «=». Записи «O(f(n)) = n» или «O(f(n)) = O(g(n))» **не имеют смысла**. Допустима расширенная форма, например **f(n) = g(n) + O(h(n))**, что означает f(n) − g(n) = O(h(n)).
:::

### Самые частые порядки (со слайдов)

константа (S(n) = 3 = Θ(1)) ≺ логарифм (W(n) = 2 + lg₂ n = Θ(log n)) ≺ линейная (A(n) = 2n + 1 = Θ(n)) ≺ линейно-логарифмическая (1,44·n log n = Θ(n log n)) ≺ квадратичная (3n² + 4 = Θ(n²)) ≺ кубическая (Θ(n³)) ≺ субэкспоненциальная (Θ(n^(log n))) ≺ экспоненциальная (Θ(2ⁿ)) ≺ факториальная (Θ(n!)).

Алгоритмы с временной сложностью выше полиномиальной считаются **непрактичными**, кроме случаев малых данных.

**Практические правила (со слайдов):**
- сумма нескольких слагаемых → порядок задаёт **доминирующее слагаемое**; многочлен имеет порядок старшего члена,
- каждая степенная функция n^α (α ∈ ℝ) имеет **свой** порядок, зависящий от α,
- логарифмический порядок только **один** — основание логарифма не важно,
- log_β n строго ниже по порядку, чем **любая** степень n^α (даже α = 0,0001),
- каждая показательная функция γⁿ имеет свой порядок в зависимости от γ, и каждая (γ > 1) строго выше по порядку любой степени n^α.

### Контрольные вопросы (со слайдов)

- Чем мы измеряем «скорость» алгоритма? Какие 2 шага нужно сделать перед анализом временной сложности?
- Определение наизусть и нахождение для данного алгоритма: доминирующей операции, размера данных, W(n), A(n) (для очень простых алгоритмов), пространственной сложности.
- Какова цель асимптотической нотации? Определения (наизусть) и интерпретация 5 вариантов.
- Доказать по определению, что выражение с асимптотической нотацией истинно или ложно, — например, **n² + 5n + 2 = O(n²)** (c = 8, n₀ = 1), но **≠ O(n)** (решение: [Тесты 2026/2027](page:exams)).

=== summary ===

## Версия 2026/2027 (M. Sydow)

- Перед анализом: **доминирующие операции** + **размер данных**.
- **W(n) = sup{t(d) : d ∈ Dₙ}**, **A(n) = Σ pₙₖ·k = E(Xₙ)**, **S(n)** (SW, SA); постоянная память: S(n) = O(1).
- 5 нотаций: Θ (=), O (≤), Ω (≥), o (<), ω (>); O: ∃c>0 ∃n₀ ∀n≥n₀ f ≤ c·g; Θ: O в обе стороны.
- Предел f/g: ∞ → ω, константа > 0 → Θ, 0 → o.
- find: W(n) = n, A(n) = (n+1)/2, SA(n) = O(1).


## Основы

- **Сложность** = расход ресурсов (время, дополнительная память) как функция **размера данных n**.
- **Доминирующая операция** — общее число операций ей пропорционально (сортировка: сравнения).
- Числа: размер = **число цифр/битов** (d ≈ log n).

## Меры

| Символ | Название | Формула |
|---|---|---|
| W(n) | пессимистическая | sup { t(d) : d ∈ Dₙ } |
| A(n) | ожидаемая | Σ k·pₙₖ |
| Δ(n) | пессимистическая чувствительность | sup { t(d₁) − t(d₂) } |
| δ(n) | ожидаемая чувствительность | dev(Xₙ) |

Последовательный поиск со сторожем: W = n+1, A = (n+1)/2, Δ = n, δ ≈ 0,29n.

## Нотации

- f = **O(g)**: ∃ c > 0, n₀: f(n) ≤ c·g(n) при n > n₀.
- f = **Ω(g)** ⇔ g = O(f); f = **Θ(g)** ⇔ и O, и Ω.
- 1 ≺ log n ≺ √n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ 2ⁿ ≺ n!.
- константы и младшие слагаемые отбрасываем; основание log не важно; log n! = Θ(n log n).

## Подсчёт сложности кода

- последовательность → **сумма** (побеждает наибольшая), цикл k раз → **умножить на k**, вложенные циклы → произведение, деление счётчика → log n.
- компьютер в p раз быстрее: время / p; для 2ⁿ размер растёт лишь на log₂ p.
- c = t / f(x); время для y: c·f(y).

## Экспоненциальный = нереализуемый

2ⁿ при n = 100 и 10⁹ оп/с ≈ 4·10¹¹ веков. Быстрое железо не спасает — спасает лучший алгоритм.

Оцените **среднюю** и **пессимистическую** временную сложность (доминирующая операция — арифметическая операция в теле цикла). Дайте её относительно значения n и относительно размера данных d (числа битов n).

```pseudo
a) sumTo(n) {
     i := 1; s := 0;
     while i <= n do { s := s + i; i := i + 1 }
     return s
   }

b) sumDown(n) {
     s := 0;
     while n > 0 do { s := s + n; n := n - 1 }
     return s
   }

c) countBits(n) {
     c := 0;
     while n > 0 do { c := c + 1; n := n div 2 }
     return c
   }
```
::hint
В a) и b) число итераций не зависит от «вида» данных — только от n. В c) n делится на 2. Помните: n ≈ 2ᵈ.
::solution
Для каждого значения n число итераций **фиксировано**, поэтому W(n) = A(n) (чувствительность 0).

- **a)** n итераций → W(n) = A(n) = **Θ(n)**. В битах: n ≈ 2ᵈ → **Θ(2ᵈ)** (экспоненциально!).
- **b)** тоже n итераций → **Θ(n)**, то есть **Θ(2ᵈ)** в битах. Отсутствие переменной `i` сложность не меняет.
- **c)** n делится на 2 до нуля → ⌊log₂ n⌋ + 1 итераций → **Θ(log n)**, а в битах ровно **d**, то есть **Θ(d)** (линейно).

Вывод: (a) и (b) считают одно и то же (сумму 1+…+n), а по формуле n(n+1)/2 получилось бы Θ(1) арифметических операций.
:::

:::task level=1 source="«Ćwiczenia 4», зад. 2 (изменено)" title="Верно или нет: порядки функций"
Рассмотрим функции переменной n ∈ ℕ. Какие утверждения верны?

1. Последовательность функций n², √n · log n, log¹⁰ n, log log n **строго убывает** по порядкам.
2. Последовательность функций n^(1/50), n^(1/3), n⁴, 2^(n/3) **строго возрастает** по порядкам.
3. n^√2 + n^√5 + n⁵ + n⁹ = O(10^(n/2) + 2^(n/3) + n^(1/2) + n^π).
4. n³ = O(n² · log n).
::hint
Сравнивайте попарно, например деля одну функцию на другую и находя предел. Помните: любая степень log проигрывает любой степени n, а любая степень n проигрывает экспоненте.
::solution
1. **Верно.** n² ≻ √n·log n (так как n²/(√n log n) = n^1,5/log n → ∞); √n·log n ≻ log¹⁰ n (степень n побеждает степень log); log¹⁰ n ≻ log log n.
2. **Верно.** 1/50 < 1/3 < 4, а 2^(n/3) — экспонента, растёт быстрее n⁴.
3. **Верно.** Левая часть = Θ(n⁹), в правой есть 10^(n/2) = (√10)ⁿ — экспонента, она доминирует над любым многочленом.
4. **Неверно.** n³/(n² log n) = n/log n → ∞, значит n³ растёт быстрее n² log n.
:::

:::task level=2 source="«Ćwiczenia 4», зад. 3 (изменено)" title="Верно или нет: нижние оценки"
«g — корректная нижняя оценка f» означает f = Ω(g); «точная» — f = Θ(g). Какие утверждения верны?

1. Функция n! — корректная нижняя оценка функции 50ⁿ + n⁵⁰ + 2^√n.
2. Функция n² — корректная (но не точная) нижняя оценка функции n³ + log n.
3. Функция n⁵⁰ — корректная нижняя оценка функции 2^√n.
4. Функция n³ — корректная и точная нижняя оценка функции n³ + 5n² log n.
::hint
В 1 сравните n! с 50ⁿ (что происходит при n > 100?). В 3 прологарифмируйте обе функции: √n против 50 · log₂ n.
::solution
1. **Неверно.** Доминирующее слагаемое — 50ⁿ, а n! растёт быстрее cⁿ для любой постоянной c (например, n!/50ⁿ → ∞). Значит, неверно, что f = Ω(n!).
2. **Верно.** n³ + log n ≥ n² начиная с некоторого n, значит f = Ω(n²); оценка не точная, так как f ≠ O(n²).
3. **Верно.** log₂(2^√n) = √n, log₂(n⁵⁰) = 50 log₂ n, а √n растёт быстрее 50 log n. Значит 2^√n = Ω(n⁵⁰) (это верно «начиная с некоторого n» — при малых n наоборот, но асимптотическая нотация это допускает).
4. **Верно.** n³ + 5n² log n = Θ(n³), так как 5n² log n = o(n³).
:::

:::task level=2 source="«Ćwiczenia 4», зад. 4 (изменено)" title="Быстрее компьютер, больше данные"
Алгоритм Alg имеет сложность f(n). Для данных размера x на компьютере K он работает t секунд. Ответьте:
- сколько времени займёт работа на K для данных **в p раз меньших**,
- каков **максимальный** размер данных, который он успеет обработать на K за t' секунд,
- сколько времени займёт работа на компьютере K', **в p' раз быстрее**, для данных размера x'.

a) f(n) = log₂ n, x = 256, t = 8 с, p = 4, t' = 10 с, p' = 4, x' = 1024
b) f(n) = n³, x = 10, t = 20 с, p = 2, t' = 160 с, p' = 8, x' = 40
c) f(n) = 2ⁿ, x = 6, t = 128 с, p = 2, t' = 2048 с, p' = 16, x' = 12
::hint
Сначала найдите c = t / f(x) — время одной «единицы» работы. Дальше всё считается как c · f(…).
::solution
**a)** c = 8 / log₂ 256 = 8/8 = 1 с.
- данные 256/4 = 64: 1 · log₂ 64 = **6 с**,
- log₂ n ≤ 10 ⇒ n = **1024**,
- 1 · log₂ 1024 / 4 = 10/4 = **2,5 с**.

**b)** c = 20 / 10³ = 0,02 с.
- данные 5: 0,02 · 125 = **2,5 с**,
- 0,02 · n³ ≤ 160 ⇒ n³ ≤ 8000 ⇒ n = **20**,
- 0,02 · 40³ / 8 = 0,02 · 64000 / 8 = **160 с**.

**c)** c = 128 / 2⁶ = 2 с.
- данные 3: 2 · 2³ = **16 с**,
- 2 · 2ⁿ ≤ 2048 ⇒ 2ⁿ ≤ 1024 ⇒ n = **10**,
- 2 · 2¹² / 16 = 8192/16 = **512 с**.

Наблюдение: для 2ⁿ компьютер в 16 раз быстрее позволяет увеличить данные всего на log₂ 16 = 4 элемента.

:::task level=3 source="«Ćwiczenia 4», зад. 5 (изменено)" title="Сложность программ, собранных из других алгоритмов"
Алгоритмы Alg₁, Alg₂, Alg₃ имеют сложность:
- T(Alg₁, n) = Θ(√n),
- A(Alg₂, n) = Θ(log n), W(Alg₂, n) = O(n),
- A(Alg₃, n) = Θ(n), W(Alg₃, n) = Ω(n²).

Определите (как можно точнее) среднюю и пессимистическую сложность:

```java
// (a)
void P(int n) { int i = n; while (i > 0) { Alg1(n); i--; } }

// (b)
void Q(int n) { for (int i = 0; i < n; i++) { Alg3(n); Alg2(n); } }

// (c)
void R(int n) {
    for (int i = 0; i < n; i++) Alg1(n);
    for (int i = 0; i < n; i++) { Alg2(n); Alg3(n); }
}

// (d)
void S(int n) {
    for (int i = 0; i < n; i++) {
        Alg1(n);
        for (int j = 0; j < n; j++) { Alg2(n); Alg3(n); }
    }
}
```
::hint
Средние сложности складываются и умножаются на число итераций. Для пессимистической: если какая-то часть известна только снизу (Ω), то и результат известен только снизу.
::solution
- **(a)** n раз по Θ(√n) → A = W = **Θ(n√n)**.
- **(b)** A = n · (Θ(n) + Θ(log n)) = **Θ(n²)**. W: каждый вызов Alg₃ может стоить Ω(n²), значит W = **Ω(n³)** (верхняя оценка неизвестна, ведь о W(Alg₃) известно лишь, что она не меньше n²).
- **(c)** A = n·√n + n·(log n + n) = **Θ(n²)**. W = **Ω(n³)** (из второго цикла).
- **(d)** A = n · (√n + n·(log n + n)) = **Θ(n³)**. W = **Ω(n⁴)**.

Заметьте: всегда W ≥ A, поэтому, например, в (b) сразу известно W = Ω(n²) — но у нас есть лучшая оценка Ω(n³).
:::
