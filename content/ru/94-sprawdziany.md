## Как выглядят задачи допуска

На практическом тесте около 10 задач, в основном на **знание работы алгоритмов**. Официальный список типов задач допуска (*zadania dopuszczeniowe*):

| № | Задача | Что нужно дать |
|---|---|---|
| 1 | **Binary Search** в массиве S, ключ Key | a) индексы элементов, сравниваемых с Key (по порядку), b) возвращаемое значение |
| 2 | **Merge Sort** (версия с лекции) | a) общее число сравнений между элементами, b) левую и правую последовательности при **последнем** вызове `merge()` |
| 3 | **partition()** из QuickSort (версия с лекции) | a) возвращаемый индекс, b) первый элемент массива после partition, c) число `swap()` — **включая последний** |
| 4 | **Count Sort** (версия с лекции) | массив `counts` (диапазон 0..max) a) после подсчёта, b) после суммирования, c) после записи в выходной массив |
| 5 | **Двоичная куча типа min** (массив с индекса 1) | a) после последовательных `insert()` элементов S, b) как a) + `delMin()`, c) после одного `construct()` из S |
| 6 | простой алгоритм **a^b** | a) спецификация, b) псевдокод (b-кратное умножение) |
| 7 | продолжение 6 | c) анализ **полной корректности**, d) **временная и пространственная** сложность (доминирующая операция, размер данных!) |

Полный объём практического теста: порядки функций / нотация O, binSearch, selection sort, insertion sort, mergeSort, quickSort/partition, countSort, radixSort, minHeap, BST, in/pre/post-order, BFS/DFS, Kruskal.

## 1. Binary Search

```pseudo
search(S, len, key){
  l = 0
  r = len - 1
  while(l <= r){
    m = (l + r)/2
    if(S[m] == key) return m
    else
      if(S[m] > key) r = m - 1
      else l = m + 1
  }
  return -1
}
```

**Официальный пример:** S = 7, 13, 17, 25, 30, 41, 52, 58, 60, 61, 80, 85; Key = 60.

```array
@idx
S: 7 13 17 25 30 [41] 52 58 60 61 80 85
```

| Шаг | l | r | m | S[m] | Решение |
|---|---|---|---|---|---|
| 1 | 0 | 11 | **5** | 41 | 41 < 60 → l = 6 |
| 2 | 6 | 11 | **8** | 60 | найдено → return 8 |

**Ответ:** a) **5, 8**; b) **8**.

:::tip
На тесте всегда пишите табличку l, r, m — одна ошибка в делении (например, (6+11)/2 = 8, а не 9) портит весь результат. Если ключа нет, возвращается −1, а сравниваемых индексов около log₂ n.
:::

## 2. Merge Sort

```pseudo
mergeSort(S, len){
  if(len <= 1) return S[0:len]
  m = len/2
  return merge(mergeSort(S[0:m], m), m,
               mergeSort(S[m:len], len-m), len-m)
}

merge(a1, len1, a2, len2){
  i = j = k = 0;
  result[len1 + len2] // (alokacja pamięci)
  while((i < len1) && (j < len2))
    if(a1[i] < a2[j]) result[k++] = a1[i++];
    else result[k++] = a2[j++];
  while(i < len1) result[k++] = a1[i++];
  while(j < len2) result[k++] = a2[j++];
  return result;
}
```

Внимание на разбиение: **m = len/2 (вниз)**, левая часть — S[0:m]; при нечётной длине **левая половина короче на 1** (например, для 7 элементов: 3 | 4). Запись S[a:b] означает элементы S[i] при a ≤ i < b.

`merge` сравнивает первые элементы обеих последовательностей и переписывает меньший; **когда одна последовательность кончается, остаток другой переписывается без сравнений**. Число сравнений в одном `merge` = число элементов, выписанных до того, как одна из последовательностей исчерпается. При **равных** элементах условие `a1[i] < a2[j]` ложно, поэтому первым идёт элемент из **правой** последовательности — эта версия не устойчива (замена `<` на `<=` делает её устойчивой; слайды спрашивают, какое место кода решает об устойчивости).

**Официальный пример:** S = 6, 2, 4, 0, 3, 8, 7, 5.

| Вызов merge | Результат | Сравнения |
|---|---|---|
| (6) + (2) | 2, 6 | 1 |
| (4) + (0) | 0, 4 | 1 |
| (2, 6) + (0, 4) | 0, 2, 4, 6 | 3 (0<2, 2<4, 4<6; затем 6 без сравнения) |
| (3) + (8) | 3, 8 | 1 |
| (7) + (5) | 5, 7 | 1 |
| (3, 8) + (5, 7) | 3, 5, 7, 8 | 3 (3<5, 5<8, 7<8; затем 8) |
| **(0, 2, 4, 6) + (3, 5, 7, 8)** | 0, 2, 3, 4, 5, 6, 7, 8 | 6 (левая кончается после 6; 7, 8 без сравнений) |

**Ответ:** a) 1+1+3+1+1+3+6 = **16**; b) последний merge: **0, 2, 4, 6 | 3, 5, 7, 8**.

:::tip
Последний `merge()` всегда сливает **две отсортированные половины всего массива** — достаточно отдельно отсортировать левую и правую половины. Число сравнений при слиянии последовательностей длины p и q — от min(p, q) до p + q − 1.
:::

## 3. partition() из QuickSort

Опорный элемент — **первый**. Два индекса идут навстречу: левый ищет элемент **больше** опорного, правый — **меньше**; если они не разминулись, меняем местами. В конце опорный элемент меняется с элементом на границе (это тоже `swap`).

```pseudo
partition(a, l, r){
  i = l + 1;
  j = r;
  p = a[l]; //"pivot"
  temp;
  do{
    while((i < r) && (a[i] <= p)) i++;
    while((j > i) && (a[j] >= p)) j--;
    if(i < j) {temp = a[i]; a[i] = a[j]; a[j] = temp;}
  }while(i < j);
  // when (i==r):
  if(a[i] > p) {a[l] = a[i - 1]; a[i - 1] = p; return i - 1;}
  else {a[l] = a[i]; a[i] = p; return i;}
}

quicksort(a, l, r){
  if(l >= r) return;
  k = partition(a, l, r);
  quicksort(a, l, k - 1);
  quicksort(a, k + 1, r);
}
```

На слайде обмен пары — три присваивания через `temp`, а финальная установка опорного (`a[l] = …; … = p`) — тоже обмен; в задачах допуска он считается последним `swap()`. Пример со слайдов: 5,2,1,7,2,6,1,3,4,8,6,0 → 3,2,1,0,2,4,1,5,6,8,6,7 (возвращает 7).

**Официальный пример:** S = 6, 5, 9, 4, 8, 3, 1, 7, 2, 0 (опорный 6).

```array
@idx
start: (6) 5 [9] 4 8 3 1 7 2 [0]
swap 1: (6) 5 0 4 [8] 3 1 7 [2] 9
swap 2: (6) 5 0 4 2 3 [1] [7] 8 9
swap 3: 1 5 0 4 2 3 {6} 7 8 9
```

1. i останавливается на 9 (индекс 2), j на 0 (индекс 9) → swap(2, 9).
2. i останавливается на 8 (индекс 4), j на 2 (индекс 8) → swap(4, 8).
3. i проходит 2, 3, 1 и останавливается на 7 (индекс 7); j спускается до i — конец цикла. a[7] = 7 > 6, поэтому p = 6 → swap(0, 6).

**Ответ:** a) **6**; b) **1**; c) **3** swap.

:::tip Быстрая проверка
Возвращаемый индекс = **число элементов меньше опорного** (если элементы различны): в примере 5, 4, 3, 1, 2, 0 → 6. Число swap = число обменов пар + 1.
:::

## 4. Count Sort

```pseudo
countSort(a, l){
  max = maxValue(a, l);
  l1 = max + 1;
  counts[l1];
  result[l];
  for(i = 0; i < l1; i++) counts[i] = 0;

  for(i = 0; i < l; i++) counts[a[i]]++;
  for(i = 1; i < l1; i++) counts[i] += counts[i - 1];
  for(i = l - 1; i >= 0; i--)
    result[--counts[a[i]]] = a[i];
}
```

Пример со слайдов: для (3,2,5,1,2,6,8,1,2,4) max = 8, counts после фазы 1: 0,2,3,1,1,1,1,0,1, после фазы 2: 0,2,5,6,7,8,9,9,10. Префиксное `--counts[a[i]]` сначала уменьшает счётчик, а потом использует его как индекс.

**Официальный пример:** S = 2, 2, 4, 2, 5, 3, 5, 2, 1, 0, 1, 5, 0, 2, 0 (max = 5, значит counts имеет индексы 0..5).

| Индекс | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| a) после подсчёта | 3 | 2 | 5 | 1 | 1 | 3 |
| b) после суммирования | 3 | 5 | 10 | 11 | 12 | 15 |
| c) после записи | 0 | 3 | 5 | 10 | 11 | 12 |

:::tip
В фазе 3 каждое `counts[v]` уменьшается ровно столько раз, сколько раз встречается v, — поэтому c) это просто b), **сдвинутое на одну позицию вправо** с 0 в начале (= индекс, с которого в результате начинаются v). Последнее значение b) всегда равно len.
:::

## 5. Двоичная куча типа min

Куча в массиве с **индекса 1**: дети узла i — 2i и 2i+1, родитель — i/2. В куче min каждый родитель ≤ детей.

- `insert(x)`: вставить в конец, затем **upheap** — менять с родителем, пока родитель > x.
- `delMin()`: забрать корень, **последний элемент перенести в корень**, затем **downheap** — менять с **меньшим** ребёнком, пока он меньше.
- `construct()`: (построение из всего массива сразу) выполнить downheap для i = n/2, n/2 − 1, …, 1.

Код со слайдов (куча в массиве, индекс 0 не используется; при равных детях downheap выбирает **левого**, так как сравнение строгое):

```pseudo
upheap(i)        // i > 0
  key = heap[i]
  parent = i/2
  while((parent > 0) && (heap[parent] > key))
    heap[i] = heap[parent]
    i = parent
    parent /= 2
  heap[i] = key

downheap(i)
  l = 2i          // lewy syn
  r = 2i + 1      // prawy syn
  if l <= n and heap[l] < heap[i]:
    min = l
  else:
    min = i
  if r <= n and heap[r] < heap[min]: // n to rozmiar kopca
    min = r
  if min != i:
    swap(i,min)   // zamiana elementów, nie samych indeksów
    downheap(min) // kontynuuj niżej

construct: for(i = n/2; i > 0; i--) downHeap(i)
```

**Официальный пример:** S = 15, 17, 3, 0, 16, 2, 19, 5.

**a) Последовательные insert():**

| Вставляем | Массив после upheap |
|---|---|
| 15 | 15 |
| 17 | 15, 17 |
| 3 | 3, 17, 15 |
| 0 | 0, 3, 15, 17 |
| 16 | 0, 3, 15, 17, 16 |
| 2 | 0, 3, 2, 17, 16, 15 |
| 19 | 0, 3, 2, 17, 16, 15, 19 |
| 5 | **0, 3, 2, 5, 16, 15, 19, 17** |

```tree
0(3(5(17,_),16),2(15,19))
```

**b) delMin():** 17 идёт в корень: 17, 3, 2, 5, 16, 15, 19 → меньший ребёнок 2 → 2, 3, 17, 5, 16, 15, 19 → меньший ребёнок 15 → **2, 3, 15, 5, 16, 17, 19**.

**c) construct()** на 15, 17, 3, 0, 16, 2, 19, 5 (n = 8, начинаем с i = 4):

| i | Узел | Действие | Массив |
|---|---|---|---|
| 4 | 0 | ребёнок 5 — без изменений | 15, 17, 3, 0, 16, 2, 19, 5 |
| 3 | 3 | дети 2, 19 → обмен с 2 | 15, 17, 2, 0, 16, 3, 19, 5 |
| 2 | 17 | дети 0, 16 → с 0; дальше ребёнок 5 → с 5 | 15, 0, 2, 5, 16, 3, 19, 17 |
| 1 | 15 | дети 0, 2 → с 0; дети 5, 16 → с 5; ребёнок 17 — стоп | **0, 5, 2, 15, 16, 3, 19, 17** |

:::warn
Результаты a) и c) **разные**, хотя обе — правильные кучи; это частая ловушка. `construct()` — не то же самое, что n раз `insert()`.
:::

## 6–7. Алгоритм a^b: спецификация, псевдокод, корректность, сложность

Эта задача проверяет определения из лекций 1 (корректность) и 2 (сложность) — см. [тему 2](topic:t02) и [тему 3](topic:t03), разделы «версия лекции 2026/2027».

**a) Спецификация**
- **имя и аргументы:** `power(a, b)`
- **предусловие:** a, b — натуральные числа, a > 0 (b может быть равно 0)
- **постусловие:** алгоритм возвращает число a^b (в частности 1 при b = 0)

**b) Псевдокод**

```pseudo
power(a, b){
  result = 1
  i = 0
  while(i < b){
    result = result * a
    i++
  }
  return result
}
```

**c) Полная корректность** = свойство остановки + частичная корректность.

1. **Свойство остановки.** Цикл заканчивается, когда i ≥ b. Значение b **постоянно и конечно** (натуральное число), i начинается с 0 и в каждой итерации **растёт на 1**. Значит, ровно после b итераций i = b и алгоритм останавливается.
2. **Частичная корректность — инвариант цикла:** `result == a^i  ∧  i <= b`.
   - **перед первой итерацией:** i = 0, result = 1 = a⁰; i = 0 ≤ b, так как b натуральное ✓
   - **сохранение:** если перед итерацией result = a^i и i < b (условие цикла), то после неё result' = a^i · a = a^(i+1) и i' = i + 1 ≤ b ✓
   - **после выхода из цикла:** инвариант и ¬(i < b) дают i = b, значит result = a^b — это постусловие ✓

Раз алгоритм обладает свойством остановки и частично корректен, он **полностью корректен**.

**d) Сложность**
- **размер данных:** значение показателя **b** (a не влияет на число операций — при условии, что умножение — одна операция),
- **доминирующая операция:** умножение `result * a` (подойдёт и сравнение `i < b`),
- **временная сложность:** W(b) = A(b) = b, то есть **Θ(b)** — линейная (сравнений b + 1, тоже Θ(b)),
- **пространственная сложность:** постоянное число переменных (result, i) → **S(b) = O(1)**.

:::exam
Без указания **доминирующей операции** и **размера данных** анализ сложности неполон — преподаватель прямо об этом напоминает. Замечание «на плюс»: относительно **числа битов** показателя (≈ log₂ b) этот алгоритм экспоненциальный (сравните с [темой 3](topic:t03)).
:::

## Тест знаний — к чему готовиться

Подсказки преподавателя к теоретической части (пересказаны близко к тексту):

1. **Корректность.** Очень хорошо знать и **понимать логический смысл** определений: полная/частичная корректность, свойство остановки, спецификация, пред-/постусловие, инвариант. Потренироваться обосновывать **свойство остановки**, а для простых алгоритмов — доказывать частичную корректность инвариантом (последнее скорее не потребуется для оценки 4,0).
2. **Сложность.** Определения временной и пространственной сложности, доминирующей операции, размера данных, пессимистической и средней сложности, обозначения **W(), A(), S()**. Определения и смысл всех **5 видов асимптотической нотации** (O, o, Θ, Ω, ω). Уметь определять порядок функции; потренироваться в доказательствах по определению (например, **n² + 5n + 2 = O(n²), но не O(n)**). Знать **иерархию порядков** (константа, логарифм, любая степень n — в том числе дробная, экспоненты). В анализе всегда объяснять, **что является размером данных** (иногда несколько переменных) и **что — доминирующей операцией** (иногда несколько, например при нескольких последовательных циклах).
3. **Поиск.** Работа и **спецификации** (что предполагается о данных) последовательного поиска, **прыжков через k** и двоичного; как они работали бы на **массиве и на связном списке**; сложности, в том числе зависимость прыжков через k от k; на каких данных алгоритм работает дольше всего.
4. **Сортировка.** Точная работа selection, insertion, merge sort (и merge), quicksort (и partition), count sort и radix sort — не только сложности наизусть. На каких данных медленнее/быстрее всего, как на массивах и как на списках; **сравнение каждой пары** алгоритмов; **устойчивость** (какие устойчивы и почему); **нижняя оценка** сортировки сравнениями (Ω(n log n)).
5. **Абстрактные структуры данных.** Отличать АСД от конкретных структур (массив, список, двоичное дерево). Определения и эффективные реализации: **стек, очередь, дек, очередь с приоритетом, словарь**; стек/очередь на массиве и на списке (одно- или двусвязном?) и сложности операций. В частности: очередь с приоритетом как **двоичная куча**, словарь как **хеш-таблица** или **BST** — определения, свойства и работа операций.

### Чек-лист со слайдов {own}

:::own
Объединённые списки «Co na pewno należy umieć» и «Pytania/zadania kontrolne» из первых двух лекций 2026/2027 — в виде для отметок.
:::

- Дать по памяти **точные** определения: спецификации, корректных входных и выходных данных, полной и частичной корректности, инварианта цикла.

:::task level=2 source="Подсказки преподавателя (пример)" title="Нотация O по определению"
Докажите по определению, что n² + 5n + 2 = O(n²), но n² + 5n + 2 ≠ O(n).
::solution
**O(n²):** при n ≥ 1 имеем 5n ≤ 5n² и 2 ≤ 2n², поэтому n² + 5n + 2 ≤ 8n². Константы: **c = 8, n₀ = 1** ✓.

**Не O(n):** предположим, что существуют c > 0 и n₀, такие что n² + 5n + 2 ≤ c·n при n ≥ n₀. Делим на n: n + 5 + 2/n ≤ c, то есть n ≤ c для всех n ≥ n₀ — противоречие (возьмите n > max(c, n₀)). ∎
:::
