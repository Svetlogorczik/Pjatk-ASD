## Очередь с приоритетом

В обычной очереди обслуживают того, кто пришёл раньше. В **очереди с приоритетом** — того, кто **важнее всех** (у кого наибольший приоритет), независимо от порядка прихода.

:::def
**Очередь с приоритетом** (динамическая задача сортировки): предложить структуру для элементов динамического множества S с операциями:
1. `construct(q, S)` — по последовательности q = [a₁, …, aₙ] создать множество S = {a₁, …, aₙ},
2. `insert(x, S)` — S := S ∪ {x},
3. `deletemax(S)` — удалить из S наибольший элемент (двойственная операция: `deletemin`).

Элементы берутся из линейно упорядоченного универсума.
:::

:::analogy
Приёмный покой в больнице: пациент с инфарктом проходит раньше пациента с вывихом, даже если пришёл позже. Решает приоритет, а не порядок прихода.
:::

Элементарные реализации (лекция):

| Реализация | construct | insert | deletemax | когда хороша |
|---|---|---|---|---|
| неупорядоченный массив | O(n) | O(1) | O(n) | много insert, мало deletemax |
| упорядоченный массив | O(n log n) | O(n) | O(1) | много deletemax, мало insert |
| **куча** | **O(n)** | **O(log n)** | **O(log n)** | всегда хорошо |

Общая схема сортировки очередью с приоритетом: `construct(q, S)`, затем n раз `deletemax(S)`. С кучей это даёт **HeapSort** со сложностью O(n log n).

## Куча

:::def
**Куча** (max, *kopiec*) — двоичное дерево, в узлах которого элементы множества S и выполнено **свойство кучи**: если x — отец y, то **элемент в x не меньше элемента в y**.
:::

Следствия:
- **наибольший элемент — в корне**,
- на каждом пути от корня к листу элементы идут **по невозрастанию**.

:::warn
Куча — **не** BST! Между левым и правым сыном в куче нет никакого порядка — известно только, что отец ≥ сыновей. Поэтому в куче нельзя быстро найти произвольный элемент, зато максимум всегда «под рукой».
:::

### Полная куча и её запись в массиве

**Полная куча** — куча, являющаяся **полным** двоичным деревом: все уровни заполнены, кроме, может быть, последнего, заполненного **слева** без пропусков. Для высоты h и числа узлов n:

2ʰ ≤ n < 2ʰ⁺¹, то есть **h = ⌊log₂ n⌋**.

Регулярная форма позволяет хранить кучу в массиве **без указателей** — узлы нумеруются по уровням слева направо, начиная с 1:

- сыновья узла k: **2k** и **2k + 1**,
- отец узла k (k > 1): **⌊k/2⌋**.

Пример кучи и её массива:

```tree
15(12(11(7,4),1),9(3,6))
```

```array
@idx 1
a: 15 12 9 11 1 3 6 7 4
```

:::tip
В Java массивы индексируются с 0. Можно либо оставить a[0] пустым (как на лекции), либо использовать формулы «с нуля»: сыновья k — **2k + 1** и **2k + 2**, отец — **(k − 1)/2** (замечание автора сайта).
:::

## Операции над кучей

### insert и upheap

Новый элемент ставим на **первое свободное место последнего уровня** (a[n+1]), а затем восстанавливаем свойство кучи: если он больше отца, **поднимаемся вверх**, сдвигая меньших отцов вниз (процедура **upheap**).

Пример: insert(13) в кучу выше. 13 попадает на позицию 10 (сын 1), он больше 1 → вверх; больше 12 → вверх; меньше 15 → стоп.

```tree caption="после insert(13)"
15(13(11(7,4),12(1,_)),9(3,6))
```

В худшем случае поднимаемся от листа до корня: **W_insert(n) = O(log n)** (около ⌊log n⌋ + 1 сравнений).

### deletemax и downheap

1. Запоминаем корень (максимум).
2. На его место переносим **последний** элемент кучи (a[n]) и уменьшаем n.
3. Восстанавливаем свойство кучи, **спускаясь вниз**: сравниваем элемент с **большим** из сыновей; если он меньше — меняем и идём дальше (процедура **downheap**).

Пример: deletemax из исходной кучи — удаляем 15, наверх идёт 4, затем 4 опускается: обмен с 12, с 11, с 7.

```tree caption="после deletemax"
12(11(7(4,_),1),9(3,6))
```

На каждом шаге **два** сравнения (какой сын больше + нужен ли обмен), а шагов не более ⌊log n⌋: **W_deletemax(n) = 2⌊log n⌋**.

### construct за линейное время

Построение кучи n операциями insert стоило бы O(n log n). Лекция показывает способ быстрее — **снизу вверх**: листья (позиции > n/2) уже являются кучами. Для i = ⌊n/2⌋, …, 1 вызываем `downheap(i)` — в этот момент поддеревья сыновей i уже кучи, поэтому после downheap поддерево i — тоже куча.

```pseudo title="construct (лекция)"
void construct()
{
  for i := n/2 downto 1 do
    downheap(i)
}
```

**Почему это O(n)?** {own}

:::own
Обоснование автора сайта (на слайдах дан только результат).
:::

downheap из узла на высоте k стоит O(k). Узлов на высоте k около n/2ᵏ⁺¹. Сумма: Σ k · n/2ᵏ⁺¹ = n · Σ k/2ᵏ⁺¹ ≤ n (так как Σ k/2ᵏ = 2). Большинство узлов внизу и «опускаются» лишь на шаг-два.

## HeapSort — пирамидальная сортировка

```pseudo title="HeapSort (лекция)"
void HeapSort()
{
  construct();
  m := n;
  for i := n downto 2 do
    a[i] := deletemax();     // куча уменьшается, освободившаяся ячейка получает максимум
}
```

Анализ с лекции: construct — O(n), n − 1 раз deletemax — O(n log n). Точнее **W(n) ≤ 2n log n + O(n)**.

- сортирует **на месте**: S(n) = O(1),
- **всегда** O(n log n) (и в худшем случае) — в отличие от QuickSort,
- **неустойчива**.

## Левосторонние (левацкие) деревья-кучи

У двоичной кучи в массиве есть слабость: **слияние двух куч** стоит O(n). Левосторонние деревья (лекция asd10 и слайды 2009 «Kolejka priorytetowa — kopiec lewicowy») делают это за O(log n).

:::def
Для узла v пусть **odl(v)** — длина **самого правого пути** от v до внешнего (пустого) узла. **Левостороннее дерево** (*drzewo lewicowe*) — двоичное дерево, в котором для каждого внутреннего узла v самый правый путь — **кратчайший** из всех путей от v к внешнему узлу, то есть odl(левый сын) ≥ odl(правый сын).
:::

- длина самого правого пути **≤ log₂(n + 1)** (дерево «тяжёлое» слева, а правый путь короткий),
- если ключи расположить в **порядке кучи**, получится **левосторонняя куча**.

**Основная операция — слияние** двух левосторонних деревьев: рекурсивно сливаем **правые пути** (больший корень остаётся корнем, а его правое поддерево сливается с другим деревом), а при возврате из рекурсии **восстанавливаем левосторонность** — при необходимости меняем местами левого и правого сына.

Остальные операции выражаются через слияние:
- `insert(x)` = слить(куча, дерево из одного x),
- `deletemax` = удалить корень и слить(левое поддерево, правое поддерево).

Стоимость каждой операции **логарифмическая**.

=== summary ===

## Очередь с приоритетом

- construct, insert, deletemax (или deletemin).
- неупорядоченный массив: insert O(1), deletemax O(n); упорядоченный — наоборот; **куча: оба O(log n), construct O(n)**.

## Куча

- свойство: отец ≥ сын ⇒ max в корне; это **не** BST.
- полная: уровни заполнены, последний слева; **h = ⌊log n⌋**.
- массив с 1: сыновья **2k, 2k+1**, отец **⌊k/2⌋** (с 0: 2k+1, 2k+2, (k−1)/2).
- **insert:** в конец + **upheap** (вверх), O(log n).
- **deletemax:** корень ← последний, **downheap** (вниз, к большему сыну), 2⌊log n⌋ сравнений.
- **construct:** downheap для i = n/2 … 1 — **O(n)**.

## HeapSort

construct + (n−1) × deletemax в конец массива; **W ≤ 2n log n + O(n)**, на месте, всегда n log n, неустойчива.

## Левосторонняя куча

- odl(левый) ≥ odl(правый); правый путь ≤ log(n+1).
- **слияние** по правым путям + обмен сыновей; insert и deletemax через слияние — O(log n).

:::task level=2 source="«ASD 10b», зад. 1 (изменено)" title="Построение кучи двумя способами"
Для последовательности **{5, 8, 3, 10, 9, 4, 2, 7, 6}** (куча типа **min** — наименьший в корне):

a) постройте кучу последовательными операциями **insert** («медленное» построение),
b) выполните над ней **delmin**,
c) постройте кучу из тех же данных методом **construct** («быстрое» построение, снизу вверх).

Дайте массивы после каждого шага.
::hint
В min-куче условие обратное: отец ≤ сын, а upheap/downheap сравнивают «в сторону меньшего». В construct начинаете с i = ⌊9/2⌋ = 4 (нумерация с 1).
::solution
**a) insert по очереди** (массив с позиции 1):

| вставлен | массив после upheap |
|---|---|
| 5 | 5 |
| 8 | 5, 8 |
| 3 | 3, 8, 5 |
| 10 | 3, 8, 5, 10 |
| 9 | 3, 8, 5, 10, 9 |
| 4 | 3, 8, 4, 10, 9, 5 |
| 2 | 2, 8, 3, 10, 9, 5, 4 |
| 7 | 2, 7, 3, 8, 9, 5, 4, 10 |
| 6 | 2, 6, 3, 7, 9, 5, 4, 10, 8 |

```tree
2(6(7(10,8),9),3(5,4))
```

**b) delmin:** удаляем 2, наверх идёт последний (8), затем 8 опускается к меньшему сыну: 8 ↔ 3, потом 8 ↔ 4. Результат: **3, 6, 4, 7, 9, 5, 8, 10**.

**c) construct** (downheap для i = 4, 3, 2, 1; начало: 5, 8, 3, 10, 9, 4, 2, 7, 6):

| i | элемент | что происходит | массив |
|---|---|---|---|
| 4 | 10 | сыновья 7, 6 → обмен с 6 | 5, 8, 3, 6, 9, 4, 2, 7, 10 |
| 3 | 3 | сыновья 4, 2 → обмен с 2 | 5, 8, 2, 6, 9, 4, 3, 7, 10 |
| 2 | 8 | сыновья 6, 9 → с 6; затем сыновья 7, 10 → с 7 | 5, 6, 2, 7, 9, 4, 3, 8, 10 |
| 1 | 5 | сыновья 6, 2 → с 2; затем сыновья 4, 3 → с 3 | **2, 6, 3, 7, 9, 4, 5, 8, 10** |

Быстрое построение сделало **6** обменов (медленное — 8 подъёмов) и дало **другую** (тоже правильную) кучу.
:::

:::task level=3 source="«ASD 10b», зад. 3 (изменено)" title="Верно или нет: быстрое построение кучи"
Пусть куча H (типа **min**) — результат работы алгоритма **construct** (быстрое построение, снизу вверх) для массива

**E = [16, 12, 2, 13, 19, 8, 9, 1, 11, 4, 3]**.

Какие утверждения верны?
1. Число обменов элементов при построении ровно 7.
2. Ключи кучи-дерева H в порядке PostOrder образуют последовательность: 13, 12, 11, 16, 19, 4, 3, 8, 9, 2, 1.
3. Число внутренних вершин кучи-дерева H ровно 6.

n = 11, значит downheap выполняется для i = 5, 4, 3, 2, 1 (нумерация с 1). Считайте каждый обмен — и те, что при спуске на несколько уровней.
::solution
| i | элемент | обмены | массив после шага |
|---|---|---|---|
| 5 | 19 | 19 ↔ 3 | 16, 12, 2, 13, 3, 8, 9, 1, 11, 4, 19 |
| 4 | 13 | 13 ↔ 1 | 16, 12, 2, 1, 3, 8, 9, 13, 11, 4, 19 |


1. **Верно** — обменов: 1 + 1 + 0 + 2 + 3 = **7**.
2. **Верно** — postorder: 13, 12, 11, 16, 19, 4, 3, 8, 9, 2, 1.

:::task level=1 source="own" title="Навигация по куче в массиве"
Полная куча содержит n = 30 элементов в массиве с индекса 1. Укажите: индекс отца и сыновей элемента на позиции 13; какие позиции — листья; какова высота кучи.
::hint
Сыновья k: 2k, 2k + 1; отец ⌊k/2⌋. Листья — позиции, у которых нет сыновей (2k > n).
::solution
- позиция 13: отец **6**, сыновья **26** и **27** (оба ≤ 30, существуют),
- листья: позиции **16…30** (при k ≥ 16 имеем 2k > 30), внутренние узлы: 1…15,
- высота: ⌊log₂ 30⌋ = **4**.
:::

:::task level=2 source="own" title="Зачем левосторонняя куча?"
Объясните, почему слияние двух левосторонних куч с n элементами в сумме стоит O(log n), а для двоичной кучи в массиве — O(n).
::hint
По какому пути идёт рекурсия в процедуре Scal (слияние)? Какой длины может быть этот путь?
::solution
Scal спускается только по **правым путям** обоих деревьев (на каждом шаге одно из деревьев теряет корень, и мы идём в его правое поддерево). В левостороннем дереве правый путь — кратчайший путь к внешнему узлу, поэтому его длина ≤ log₂(n + 1). Суммарная длина обоих правых путей — O(log n): столько шагов рекурсии, каждый — O(1) работы.

Двоичные кучи в массивах нельзя «склеить» указателями — нужно переписать элементы в один массив и построить кучу заново (construct) — **O(n)**.
:::
