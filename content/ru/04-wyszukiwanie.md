## Задача поиска

Есть последовательность (массив), и мы спрашиваем: **есть ли в ней элемент a, и если да — на какой позиции?** Это одна из самых частых задач в информатике: найти контакт в телефоне, товар в магазине, слово в словаре.

Насколько быстро мы можем искать, зависит от того, **что мы знаем о данных**:

- данные **неупорядочены** → нужно (в худшем случае) просмотреть всё,
- данные **отсортированы** → можно искать гораздо хитрее.

## Последовательный (линейный) поиск

Смотрим элементы по очереди слева направо. Версию **со сторожем** мы знаем из темы 3: кладём искомое `a` в конец массива, и циклу не нужно проверять выход за границу.

- W(n) = n + 1 сравнений, A(n) = (n + 1)/2.

**Можно ли быстрее для неупорядоченных данных?** Нет. Лекция обосновывает это так: если единственная доступная операция — сравнение искомого с элементом массива, то алгоритм, который **не посмотрел** на какую-то позицию, не может знать, нет ли `a` именно там. Значит, n сравнений **необходимы**.

## Бинарный поиск

Пусть массив **отсортирован по неубыванию**. Теперь одно сравнение даёт гораздо больше информации!

:::analogy
Игра «я загадал число от 1 до 100». Вы не спрашиваете «это 1? это 2? это 3?», а спрашиваете «больше 50?». Каждый вопрос **отсекает половину** вариантов, и примерно за 7 вопросов вы знаете всё (2⁷ = 128 ≥ 100). Так же ищут слово в бумажном словаре.
:::

Идея (та же, что для корня в теме 2): держим отрезок `[l, p]`, в котором `a` **точно** есть (если он вообще есть в массиве), и сравниваем `a` со **средним** элементом `L[s]`:

- если `a > L[s]` — слева от s (включительно) искать нечего, значит `l := s + 1`,
- иначе — `a` (если есть) лежит в `[l, s]`, значит `p := s`.

Заканчиваем, когда в отрезке остался 1 элемент.

:::def
**Инвариант** бинарного поиска: *если `a` есть в массиве L, то хотя бы одна его копия лежит в рассматриваемом отрезке `L[l..p]`.* Когда в конце отрезок из одного элемента, достаточно проверить этот элемент.
:::

```pseudo title="SzukajBin (версия с лекции)"
Algorytm SzukajBin(L, N, a):
  Dane:  N > 0, L[0..N-1] отсортирован по неубыванию, a - искомый элемент
  Wynik: i, такое что L[i] = a (0 ≤ i ≤ N-1), или N, если a нет в L
{
  l := 0;  p := N - 1;
  while l < p do {
    // Инв.: a ∈ L  ⇔  a ∈ L[l..p]
    s := (l + p) div 2;          // div = целочисленное деление
    if a > L[s] then
      l := s + 1
    else
      p := s;
  }
  if a = L[l] then return l
  else return N
}
```

**Пример:** ищем 17 в `[1, 3, 5, 10, 17, 30, 35, 99]`:

```array
@idx
старт: 1 3 5 [10] 17 30 35 99
l=4: ~1~ ~3~ ~5~ ~10~ 17 [30] 35 99
p=5: ~1~ ~3~ ~5~ ~10~ [17] 30 ~35~ ~99~
p=4: ~1~ ~3~ ~5~ ~10~ {17} ~30~ ~35~ ~99~
```

1. l = 0, p = 7, s = 3: 17 > 10 → l = 4,
2. l = 4, p = 7, s = 5: 17 ≤ 30 → p = 5,
3. l = 4, p = 5, s = 4: 17 ≤ 17 → p = 4,
4. l = p = 4: `L[4] = 17` → результат **4**.

### Сложность

Каждая итерация уменьшает отрезок (примерно) **вдвое**. Из отрезка длины N после k итераций остаётся около N/2ᵏ, поэтому цикл выполнится около **⌈log₂ N⌉ раз** (плюс одно сравнение в конце). Для миллиона элементов — всего ~20 сравнений вместо миллиона!

- **W(N) ≈ log₂ N** — **логарифмическая** сложность.
- **Остановка:** величина p − l натуральная и строго убывает на каждой итерации (так как l ≤ s < p).

:::tip
Эта версия всегда возвращает **первое** вхождение `a` (наименьший индекс), даже если `a` встречается много раз, — потому что при равенстве (`a ≤ L[s]`) мы всегда идём влево (`p := s`).
:::

:::warn
Бинарный поиск работает **только на отсортированном** массиве. На неотсортированном он может не найти элемент, который там есть.
:::

### Другие методы для отсортированных данных

Старые слайды (2009, «Problem wyszukania I») показывают ещё два метода:

- **Прыжки по k** — проверяем каждый k-й элемент, а когда «перепрыгнули» `a`, просматриваем последний блок линейно. Лучшее k — около **√n**, сложность **O(√n)**.
- **Интерполяционный поиск** — вместо середины проверяем позицию, «пропорциональную» значению (как в телефонной книге: фамилию на «Я» ищем ближе к концу). Для **равномерно распределённых** данных в среднем **O(log log n)**, но в худшем случае **O(n)**.

## Максимум: n − 1 сравнений — это минимум

Поиск наибольшего элемента требует n − 1 сравнений (каждый элемент, кроме победителя, должен кому-то «проиграть»). Можно ли меньше? Лекция доказывает, что **нет**:

:::def
Построим граф: вершины — элементы, ребро соединяет два элемента, которые алгоритм сравнил. Граф с n вершинами и менее чем n − 1 рёбрами **несвязен** — у него минимум две части, элементы которых никогда не сравнивались между собой. Максимум может быть в любой из них, поэтому алгоритм не может быть уверен в ответе. Значит, **сложность задачи максимума равна n − 1 сравнений**.
:::

Обратите внимание на важное понятие: говоря о **сложности задачи**, мы рассматриваем **все возможные** алгоритмы, а не один.

## Минимум и максимум одновременно — «разделяй и властвуй»

Если искать минимум и максимум отдельно, получится 2n − 2 сравнений. Лекция «Dziel i rządź» показывает способ лучше: делим массив на две половины, находим (min, max) в каждой, а затем объединяем: min из двух минимумов, max из двух максимумов.

- T(1) = 0, T(2) = 1, T(n) = 2T(n/2) + 2,
- решение для n = 2ᵏ: **T(n) = (3/2)·n − 2**.

:::def
**Теорема Поля:** задачу одновременного нахождения минимума и максимума нельзя решить меньше чем за **⌈3n/2⌉ − 2** сравнений. (Доказательство: L. Banachowski, A. Kreczmar «Elementy analizy algorytmów».)
:::

## Второй по величине — турнир

Со слайдов 2009: ищем **второй по величине** элемент. Идея теннисного турнира: элементы играют «матчи» парами, победитель (больший) проходит дальше. После n − 1 матчей мы знаем чемпиона (максимум).

Кто второй? **Только тот, кто проиграл непосредственно чемпиону!** (Любой другой проиграл кому-то, кто не чемпион, значит, он максимум третий.) Чемпион сыграл ⌈log₂ n⌉ матчей, поэтому берём максимум из ⌈log₂ n⌉ кандидатов.

- всего: **n + ⌈log₂ n⌉ − 2** сравнений (вместо 2n − 3 наивно).

```text title="Турнир для [7, 3, 12, 9, 15, 4, 11, 6]"
раунд 1:   7  3 | 12  9 | 15  4 | 11  6     →   7, 12, 15, 11
раунд 2:     7 12   |     15 11             →   12, 15
финал:           12  15                     →   15 (максимум)
проиграли 15:  4 (р1), 11 (р2), 12 (финал) →  второй = max(4, 11, 12) = 12
сравнений: 7 (турнир) + 2 (кандидаты) = 9 = 8 + 3 - 2
```

## Выбор k-го элемента — алгоритм Хоара

**Задача:** найти элемент, который стоял бы на k-й позиции, если бы последовательность отсортировали (например, **медиану**: k = ⌈n/2⌉). Можно, конечно, отсортировать (O(n log n)) и взять k-й. Но можно быстрее — **в среднем за линейное время**.

### Функция partition (разбиение)

Самая важная часть алгоритма. Берём **опорный элемент** (pivot, *element dzielący*) `v = a[l]` и переставляем фрагмент `a[l..r]` так, чтобы:

1. `v` встал на своё **окончательное** место j (где он был бы после сортировки),
2. слева от j были элементы **≤ v**,
3. справа от j были элементы **≥ v**.

Делаем это двумя указателями: `i` идёт слева и останавливается на элементе ≥ v, `j` идёт справа и останавливается на элементе ≤ v. Эти два элемента «не на своей стороне» — меняем их местами. Когда указатели разминутся, ставим v на позицию j.

Пример: partition для `[7, 2, 9, 4, 8, 1, 6]`, v = 7:

```array
@idx
старт: (7) 2 [9] 4 8 1 [6]
обмен: (7) 2 6 4 [8] [1] 9
обмен: (7) 2 6 4 1 8 9
конец: 1 2 6 4 {7} 8 9
```

1. i останавливается на 9 (поз. 2), j на 6 (поз. 6) → обмен,
2. i останавливается на 8 (поз. 4), j на 1 (поз. 5) → обмен,
3. i останавливается на 8 (поз. 5), j на 1 (поз. 4) — разминулись → цикл закончен,
4. меняем опорный с `a[j] = a[4]`: 7 попадает на позицию **4** — это его место в отсортированной последовательности.

### Алгоритм Select

После partition мы знаем, что опорный стоит на позиции j, а в `a[l..j]` лежит `j − l + 1` элементов (опорный и меньшие). Сравниваем это число с k:

- `k = j − l + 1` → **опорный и есть ответ**,
- `k < j − l + 1` → ищем дальше **в левой части** `a[l..j−1]`,
- `k > j − l + 1` → ищем в **правой части** `a[j+1..p]`, но уже (k − (j − l + 1))-й элемент (столько меньших мы «отбросили»).

```pseudo title="Select — алгоритм Хоара"
Algorytm Select(a, n, k):
// a[0..n-1] - последовательность, k - «ранг» искомого элемента (1..n)
{
  l := 0;  p := n - 1;
  jest := false;                   // «найден»
  while not jest do {
    j := partition(a, l, p);
    // a[l..j-1] <= a[j] <= a[j+1..p]
    if k = j - l + 1 then jest := true
    else if k <= j - l then
      p := j - 1                   // k-й в левой части
    else {
      k := k - (j - l + 1);        // пропускаем j-l+1 наименьших
      l := j + 1
    }
  }
  return a[j]
}
```

### Сложность алгоритма Хоара

- partition на фрагменте длины n делает около n сравнений,
- **в худшем случае** опорный всегда крайний, и фрагмент уменьшается лишь на 1: W(1) = 0, W(n) = (n + 1) + W(n − 1), откуда **W(n) = ½n² + O(n)**,
- **в лучшем случае** попадаем сразу: n + 1 сравнений,
- **в среднем** алгоритм работает за **линейное время**: A(n) = O(n) (фрагмент в среднем сокращается на постоянную долю).

:::info
Старые слайды (2009, «Problem wyszukania II») упоминают алгоритм **«магических пятёрок»** (Blum, Floyd, Pratt, Rivest, Tarjan): опорный выбирается как медиана медиан групп по 5 элементов. Это гарантирует хорошее разбиение и **линейное время даже в худшем случае**, но с большой константой — на практике чаще используют алгоритм Хоара.
:::

=== summary ===

## Поиск

| Метод | Требование | Сложность |
|---|---|---|
| последовательный (со сторожем) | нет | W = n + 1, A = (n+1)/2 |
| бинарный | массив отсортирован | ~⌈log₂ n⌉ итераций + 1 сравнение |
| прыжки по √n | отсортирован | O(√n) |
| интерполяционный | отсортирован, равномерное распределение | в среднем O(log log n), худший O(n) |

- Неупорядоченные данные: n сравнений необходимы.
- **SzukajBin:** `s := (l+p) div 2; if a > L[s] then l := s+1 else p := s`; инвариант: a ∈ L ⇔ a ∈ L[l..p]; возвращает **первое** вхождение; убывающая функция p − l.

## Выбор

- **max:** n − 1 сравнений — сложность **задачи** (графовое доказательство: < n − 1 рёбер ⇒ несвязный граф).
- **min и max вместе:** T(n) = 2T(n/2) + 2 ⇒ **3n/2 − 2**; теорема Поля: ≥ ⌈3n/2⌉ − 2.
- **второй по величине:** турнир, **n + ⌈log₂ n⌉ − 2** (кандидаты = проигравшие чемпиону).

## Хоар (k-й элемент)

- **partition(l, r):** v = a[l]; i слева до ≥ v, j справа до ≤ v, обмен; в конце v на позицию j.
- k = j − l + 1 → найден; k ≤ j − l → p := j − 1; иначе k := k − (j − l + 1), l := j + 1.
- W(n) = ½n² + O(n), A(n) = O(n); «магические пятёрки» — O(n) даже в худшем случае.

:::task level=2 source="Ćwiczenia 3, зад. 3 — вторая часть (изменено)" title="Корректность и сложность SzukajBin"
Докажите полную корректность алгоритма SzukajBin (инвариант + остановка) и оцените его пессимистическую сложность для массива длины N.
::hint
Инвариант: «если a есть в массиве, то он в L[l..p]». Покажите, что ни одна из двух веток `if` не выбрасывает из отрезка единственное возможное место a. Убывающая функция: p − l.
::solution
**α:** N > 0, L отсортирован по неубыванию. **β:** результат i с L[i] = a, если a ∈ L; результат N, если a ∉ L.

**Инвариант** g: (a ∈ L ⇒ a ∈ L[l..p]) ∧ 0 ≤ l ≤ p ≤ N − 1.
- **начало:** l = 0, p = N − 1 — отрезок = весь массив ✓.
- **итерация:** s = (l+p) div 2, значит l ≤ s < p.
  - если a > L[s], то (L отсортирован) a > L[l..s], то есть a нет в L[l..s]; после l := s + 1 инвариант сохраняется ✓,
  - если a ≤ L[s], то все элементы L[s+1..p] ≥ L[s] ≥ a — если a есть в L[l..p], то его первое вхождение в L[l..s]; после p := s инвариант сохраняется ✓.
- **конец:** ¬(l < p) и l ≤ p ⇒ l = p. Из g: если a ∈ L, то a = L[l]. Значит, `if a = L[l]` возвращает правильный результат ✓.

**Остановка:** f = p − l ∈ ℕ; так как l ≤ s < p, в ветке «l := s + 1» l строго растёт, а в ветке «p := s» p строго убывает — f строго убывает ✓.

**Сложность:** после каждой итерации длина отрезка (p − l + 1) падает с m до не более ⌈m/2⌉. После ⌈log₂ N⌉ итераций остаётся 1 элемент. W(N) = **⌈log₂ N⌉ + 1** сравнений (+1 — финальное сравнение) = **Θ(log N)**.
:::

:::task level=2 source="Ćwiczenie 5, зад. 4 (изменено)" title="Алгоритм Хоара шаг за шагом"
Покажите работу алгоритма Хоара (с функцией partition с лекции, опорный = первый элемент отрезка) при поиске **6-го наименьшего** элемента массива

`S = [12, 5, 3, 14, 8, 19, 6, 1, 15, 17, 16, 2, 13, 5, 27, 22]`.
::hint
После каждого partition найдите ранг опорного в отрезке: j − l + 1 — и сравните с k. Не забудьте уменьшить k, когда идёте вправо.
::solution
**1. partition(0, 15)**, v = 12:
- i останавливается на 14 (поз. 3), j на 5 (поз. 13) → обмен,
- i останавливается на 19 (поз. 5), j на 2 (поз. 11) → обмен,
- i останавливается на 15 (поз. 8), j на 1 (поз. 7) — разминулись,
- 12 встаёт на позицию 7:

```array

после 1.: 1 5 3 5 8 2 6 {12} 15 17 16 19 13 14 27 22
```
Ранг опорного = 7 − 0 + 1 = 8; k = 6 < 8 → **левая часть**, p = 6.

**2. partition(0, 6)**, v = 1: меньших нет — 1 остаётся на позиции 0. Ранг = 1; k = 6 > 1 → **правая часть**: k = 6 − 1 = **5**, l = 1.

**3. partition(1, 6)**, v = 5 (фрагмент `[5, 3, 5, 8, 2, 6]`):
- i останавливается на 5 (поз. 3), j на 2 (поз. 5) → обмен → `[5, 3, 2, 8, 5, 6]`,
- i останавливается на 8 (поз. 4), j на 2 (поз. 3) — разминулись,
- 5 встаёт на позицию 3 → фрагмент `[2, 3, 5, 8, 5, 6]`.

Ранг = 3 − 1 + 1 = 3; k = 5 > 3 → **правая часть**: k = 5 − 3 = **2**, l = 4.

**4. partition(4, 6)**, v = 8 (фрагмент `[8, 5, 6]`): больших нет → 8 встаёт на позицию 6, фрагмент `[6, 5, 8]`. Ранг = 3; k = 2 ≤ 2 → **левая часть**, p = 5.

**5. partition(4, 5)**, v = 6 (фрагмент `[6, 5]`): 6 встаёт на позицию 5 → `[5, 6]`. Ранг = 5 − 4 + 1 = 2 = k → **найден**.


**Ответ: 6.** (Проверка: отсортированная последовательность 1, 2, 3, 5, 5, **6**, 8, 12, … — шестой элемент равен 6 ✓.)

:::task level=1 source="own" title="Сколько сравнений для min и max?"
Сколько сравнений сделает метод «парами» (или «разделяй и властвуй»), ища одновременно минимум и максимум в массиве из **n = 10** элементов, и сколько при **n = 11**? А сколько — наивный подход (отдельно min, отдельно max)?
::hint
Для чётного n: 1 сравнение первой пары + 3 сравнения на каждую следующую пару. Для нечётного первый элемент сразу и min, и max.
::solution
- n = 10: 1 + 3 · 4 = **13** = 3·10/2 − 2.
- n = 11: 0 + 3 · 5 = **15** = ⌈3·11/2⌉ − 2.
- Наивно: 2n − 2 → **18** и **20**.

По теореме Поля меньше нельзя.
:::
