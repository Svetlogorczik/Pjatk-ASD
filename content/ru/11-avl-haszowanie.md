## Зачем балансировать деревья?

Из темы 10 мы знаем, что операции над BST стоят O(h), а h может быть до n − 1 (например, при вставке отсортированных данных). Лекция asd9 анонсирует решение — **деревья AVL**, гарантирующие search, insert и delete за **O(log n)** всегда.

## Дерево AVL

:::def
**Дерево AVL** (Адельсон-Вельский и Ландис, 1962) — это BST, в котором для **каждого** узла высоты левого и правого поддеревьев отличаются **не более чем на 1**.

**Коэффициент баланса** (balance factor) узла v:
**BF(v) = h(левое поддерево) − h(правое поддерево)**, а в дереве AVL **BF(v) ∈ {−1, 0, +1}**.
(Высота пустого поддерева = −1.)
:::

:::analogy
Представьте подвесной мобиль над детской кроваткой: каждое плечо должно быть примерно уравновешено. Если одна сторона стала на два «этажа» тяжелее, нужно перевесить элементы — это и есть **поворот** (ротация).
:::

Пример дерева AVL с записанными коэффициентами BF (маленькое красное число):

```tree
20[0](10[1](5[0],_),30[-1](_,40[0]))
```

### Сколько узлов у дерева AVL высоты h?

- **максимум:** полное двоичное дерево — **2ʰ⁺¹ − 1** узлов,
- **минимум:** обозначим N(h). Самое «редкое» дерево AVL высоты h — это корень, одно поддерево высоты h − 1 и другое высоты h − 2 (оба тоже самые редкие):

**N(0) = 1, N(1) = 2, N(h) = N(h − 1) + N(h − 2) + 1.**

По очереди: 1, 2, 4, 7, 12, 20, 33, … Это числа Фибоначчи минус 1: **N(h) = Fₕ₊₃ − 1**. Поскольку Фибоначчи растут экспоненциально (φʰ), высота дерева AVL с n узлами **логарифмическая**: h < 1,44·log₂(n + 2), то есть **h = O(log n)**.

:::tip
Снова числа Фибоначчи — как в худшем случае алгоритма Евклида (тема 1)! Хороший пример того, что одна и та же математика появляется в очень разных местах.
:::

## Вставка в AVL

1. Вставляем ключ как в обычное BST (новый лист).
2. Поднимаемся по пути от нового листа к корню, **пересчитывая BF**.
3. Первый узел, где |BF| = 2, исправляем **поворотом**. После одного поворота (одинарного или двойного) при вставке всё дерево снова AVL.

Четыре случая (название говорит, где «избыток»: в **L**евом поддереве **L**евого сына и т. д.):

| Случай | BF узла | BF сына с тяжёлой стороны | Исправление |
|---|---|---|---|
| **LL** | +2 | +1 (или 0) | одинарный поворот **вправо** |
| **RR** | −2 | −1 (или 0) | одинарный поворот **влево** |
| **LR** | +2 | −1 | двойной: влево у сына, затем вправо |
| **RL** | −2 | +1 | двойной: вправо у сына, затем влево |

### Одинарный поворот (случай LL)

У узла y слишком высокое левое поддерево, а «избыток» — с левой стороны его левого сына x. Поворачиваем: x поднимается, y опускается вправо, а среднее поддерево B переходит от x к y (порядок BST A < x < B < y < C сохраняется).

```tree caption="до: случай LL в узле y"
y(x(A,B),C)
```

```tree caption="после поворота вправо"
x(A,y(B,C))
```

### Двойной поворот (случай LR)

Избыток — с **правой** стороны левого сына x (в его правом сыне y). Одного поворота мало — делаем два: сначала влево вокруг x, потом вправо вокруг z. В итоге y поднимается наверх.

```tree caption="до: случай LR в узле z"
z(x(A,y(B,C)),D)
```

```tree caption="после двойного поворота"
y(x(A,B),z(C,D))
```

:::exam
Типичная задача на занятиях: «вставляйте элементы по очереди в пустое дерево AVL, пересчитывайте BF и выполняйте повороты». Делайте это **по одному элементу**: вставка → пересчёт BF по пути вверх → если где-то ±2, назовите случай (LL/RR/LR/RL) и нарисуйте дерево после поворота.
:::

## Удаление из AVL

1. Удаляем как из BST (лист / один сын / последователь).
2. Поднимаемся вверх, пересчитывая BF; везде, где |BF| = 2, — поворот.

Отличия от вставки:
- при удалении может понадобиться **несколько поворотов** (даже на каждом уровне — O(log n)),
- появляется случай, когда у сына с тяжёлой стороны **BF = 0** — тогда достаточно **одинарного** поворота.

## Словарь в хеш-таблице

Деревья дают O(log n). Можно ли быстрее? Да — **в среднем O(1)**, — если не нужен порядок (min, max, последователь), а только search/insert/delete. Идея со слайдов 2009: храним элементы в массиве T[0..m−1], а позицию определяет **хеш-функция**.

:::def
- **Хеш-функция** h: ключ → {0, 1, …, m−1}, например **h(k) = k mod m**.
- **Коллизия** — у двух разных ключей одинаковое значение h.
- **Коэффициент заполнения** α = n/m (n — число элементов, m — размер таблицы).
:::

:::analogy
Гардероб в театре: номерок сразу указывает на крючок — вы не перебираете все пальто. Хеш-функция «выдаёт номерки». Проблемы начинаются, когда двое получили одинаковый номер, — это коллизия.
:::

:::tip
Размер таблицы m лучше выбирать **простым числом**, не близким к степени двойки, — тогда k mod m лучше разбрасывает ключи (совет автора сайта).
:::

### Метод цепочек

В каждой ячейке T[i] храним **список** элементов с h(k) = i. Insert — дописать в список, search/delete — просмотреть один список.

- средняя стоимость: **O(1 + α)**; при α = O(1) — константа,
- в худшем случае: все ключи в одном списке — O(n).

### Открытая адресация

Все элементы хранятся в самой таблице. При коллизии проверяем следующие ячейки по фиксированному правилу (**последовательность проб**):

- **линейное:** h(k, i) = (h(k) + i) mod m — соседние ячейки; просто, но образуются «кластеры»,
- **квадратичное:** h(k, i) = (h(k) + c₁i + c₂i²) mod m,
- **двойное хеширование:** h(k, i) = (h₁(k) + i·h₂(k)) mod m — лучше всего рассеивает ключи.

:::warn
При открытой адресации **нельзя** просто очистить ячейку при удалении — это разорвёт последовательность проб, и другие ключи станут «невидимыми». Удалённую ячейку помечают специальным маркером **«удалено»** (поиск идёт через неё дальше, вставка может её занять).
:::

## Версия лекции 2026/2027 (M. Sydow) — «Słowniki» (хеш-таблицы, AVL)

:::exam
На тесте знаний: хеш-таблицы (хеш-функция, коллизии, коэффициент заполнения α, сложность O(α)) и **определение и идея дерева AVL** — типовая задача: **вычислить bf для всех узлов и решить, AVL ли это**. Повороты **не** разбираются. Тренировочная задача: [Тесты 2026/2027](page:exams).
:::

**Прямая адресация.** Если ключи — натуральные числа из [0, …, m−1], словарь — это массив, индексируемый ключом: все операции **O(1)**. Две проблемы: память пропорциональна наибольшему возможному значению ключа (m), а не числу хранимых ключей; работает только для натуральных ключей.

:::def Хеш-таблица (tablica mieszająca)
Расширяет прямую адресацию **хеш-функцией** hash : U → [0, …, m−1] (U — универсум ключей), переводящей ключ в индекс. Память пропорциональна m (а не |U|), а тип ключа может быть любым.
:::

**Коллизии.** Обычно m < |U|, поэтому функция не инъективна: для некоторых k1 ≠ k2 hash(k1) == hash(k2) — это **коллизия**. Методы: **многократное хеширование** (если место занято, хешируем снова воспроизводимым способом до свободного места; минус: максимум m элементов) и **метод цепочек** (в каждой ячейке — список элементов, просматриваемый линейно).

**Требуемые свойства хеш-функции:** (1) вычисляется очень быстро (за постоянное время); (2) **равномерная загрузка** — для ключа из равномерного распределения на U каждое значение из [0, …, m−1] равновероятно. **Коэффициент заполнения α = n/m** (n — число пар в таблице). Благодаря (2) пессимистическая сложность операций близка к **O(α)** (списки имеют длину около α). Простейшая функция для целых чисел: **hash(key) = key mod m** (быстрая — при m, равном степени 2, достаточно взять последние log₂(m) бит; равномерная). Иногда требуется ещё и трудная обратимость (например, MD5) — modulo этому не удовлетворяет.

**Итог:** хеш-таблицы дают операции словаря за **O(α)** и позволяют балансировать время и память параметром m (больше m — быстрее, но больше памяти). Они **не** поддерживают эффективно операции упорядоченного словаря (минимум, максимум, последователь, предшественник — линейно).

:::def Дерево AVL
(Адельсон-Вельский, Ландис) — BST с дополнительным условием. **Коэффициент сбалансированности** узла x: **bf(x) = высота левого поддерева x − высота правого поддерева x**. Дерево AVL — это BST, в котором для каждого узла **bf(x) ∈ {−1, 0, 1}**.
:::

Можно доказать, что пессимистическая высота дерева AVL — **O(log n)**, поэтому все операции упорядоченного словаря имеют **логарифмическую пессимистическую сложность**. Пример со слайдов: в дереве 8(3(_, 6(5, _)), 12(_, 15(13, 20))) bf(8) = 0, bf(3) = −2, bf(12) = −2, bf(6) = +1, остальные 0 — **это не AVL**. **Реализация:** после каждой модифицирующей операции (как в BST) проверяем bf, идя **вверх** от изменённого узла (только там bf мог измениться, не более чем на 1); при bf = 2 или −2 фрагмент исправляется **поворотом** за O(1). Поэтому W(n) = O(log n) для всех операций. Есть и другие структуры (самоорганизующиеся деревья, B-деревья, AB-деревья, B+…).

=== summary ===

## Версия 2026/2027 (M. Sydow)

- Hash: U → [0..m−1]; коллизии: многократное хеширование / цепочки; α = n/m; операции O(α); hash = key mod m.
- AVL: bf(x) = h(лев.) − h(прав.) ∈ {−1, 0, 1}; высота O(log n), W = O(log n); исправление поворотами O(1).


## AVL

- BST, где для каждого узла **|h(L) − h(R)| ≤ 1**; **BF = h(L) − h(R) ∈ {−1, 0, 1}**.
- максимум узлов при высоте h: **2ʰ⁺¹ − 1**; минимум: **N(h) = N(h−1) + N(h−2) + 1**, N(0) = 1, N(1) = 2 (1, 2, 4, 7, 12, 20, 33) = Fₕ₊₃ − 1 ⇒ **h = O(log n)** (< 1,44 log₂ n).
- insert: вставка BST + пересчёт BF вверх + **один** (одинарный или двойной) поворот.
- случаи: **LL** → поворот вправо; **RR** → влево; **LR** → влево у сына + вправо; **RL** → вправо у сына + влево.
- delete: удаление BST + повороты вверх (может быть много); сын с BF = 0 → одинарный поворот.

## Хеширование

- h(k) = k mod m; коллизии; α = n/m.
- **цепочки:** список в каждой ячейке; в среднем O(1 + α).
- **открытая адресация:** линейная (h(k)+i), квадратичная, двойная; удаление = маркер «удалено».
- в среднем O(1), но нет порядка (min, max, последователь — дорого).

| 25 | — | — | 20(10, 30(25, _)) |

| 5 | — | — | 20(10(5, _), 28(25, 30)) |
| 3 | BF(10) = +2, BF(5) = +1 | **LL** → вправо вокруг 10 | 20(5(3, 10), 28(25, 30)) |
| 40 | — | — | 20(5(3, 10), 28(25, 30(_, 40))) |
| 35 | BF(30) = −2, BF(40) = +1 | **RL** → вправо вокруг 40, влево вокруг 30 | 20(5(3, 10), 28(25, 35(30, 40))) |
| 38 | BF(28) = −2, BF(35) = −1 | **RR** → влево вокруг 28 | 20(5(3, 10), 35(28(25, 30), 40(38, _))) |

Итоговое дерево с BF:

```tree
20[-1](5[0](3[0],10[0]),35[0](28[0](25[0],30[0]),40[1](38[0],_)))
```

:::task level=3 source="Ćwiczenie 9, зад. 2 (изменено)" title="Удаление из дерева AVL"
Из дерева, полученного в предыдущей задаче, удалите сначала узел **5**, а затем узел **3**. Пересчитайте BF и выполните нужные повороты (при двух сыновьях используйте последователя).
::hint
У 5 два сына — его последователь 10. После удаления 3 левое поддерево корня сильно «сожмётся».
::solution
**delete(5):** у 5 сыновья 3 и 10 → последователь 10 занимает место 5 → поддерево 10(3, _), BF(10) = +1, BF(20) = h(L) − h(R) = 1 − 2 = −1 — **без поворота**:

```tree
20[-1](10[1](3,_),35[0](28(25,30),40[1](38,_)))
```

**delete(3):** 10 становится листом (высота 0), а правое поддерево корня имеет высоту 2 → **BF(20) = −2**. У правого сына 35 BF = 0 → достаточно **одинарного поворота влево** вокруг 20 (случай, который бывает только при удалении):

```tree
35[1](20[-1](10,28(25,30)),40[1](38,_))
```

Дерево снова AVL (BF(35) = 2 − 1 = +1, BF(20) = 0 − 1 = −1).
:::

Самое редкое дерево AVL для h = 3 (7 узлов), пример формы:

```tree
d(b(a(x,_),c),e(_,f))
```

Левое поддерево высоты 2 (4 узла), правое — высоты 1 (2 узла): 1 + 4 + 2 = 7 ✓. (Буквы вместо ключей — важна только форма; ключи можно расставить так, чтобы это было BST.)

:::task level=1 source="own" title="Назовите случай"
В дереве AVL после вставки нового ключа первый несбалансированный узел v имеет BF(v) = −2, а его правый сын — BF = +1. Какой это случай и какие повороты нужны? А если бы у правого сына было BF = −1?
::hint
Минус значит «слишком высоко справа». Знак BF сына говорит, с какой стороны сына избыток.
::solution
- BF(v) = −2, BF(правого сына) = +1 → случай **RL**: сначала поворот **вправо** вокруг правого сына, затем поворот **влево** вокруг v.
- BF(правого сына) = −1 → случай **RR**: один поворот **влево** вокруг v.
:::
