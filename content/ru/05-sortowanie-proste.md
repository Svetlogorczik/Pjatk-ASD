## Задача сортировки

Сортировка — одна из задач, которые компьютеры решают чаще всего. Причина проста: **упорядоченными данными гораздо легче пользоваться** (вспомните словарь, телефонную книгу или бинарный поиск из темы 4).

:::def
**Сортировка:** дана последовательность q = [a₀, a₁, …, aₙ₋₁] элементов линейно упорядоченного множества. Нужно найти такую перестановку элементов, чтобы получилась **неубывающая** последовательность: a₀ ≤ a₁ ≤ … ≤ aₙ₋₁.
:::

Договорённости с лекции:

- **доминирующая операция:** сравнение двух элементов (иногда считают и обмены/перемещения),
- **сложность по памяти S(n):** сколько **дополнительной** памяти нужно (сверх самой последовательности),
- элементы хранятся в массиве `a[i]`, 0 ≤ i < n,
- при анализе среднего случая считаем, что **все перестановки** данных равновероятны.

### Два важных свойства алгоритмов сортировки

:::def
- Алгоритм сортирует **на месте** (*w miejscu*), если ему нужна только **постоянная** дополнительная память: S(n) = O(1).
- Алгоритм **устойчивый** (*stabilny*), если элементы с **равными** ключами остаются в том же взаимном порядке, что и до сортировки.
:::

:::analogy
Устойчивость: у вас список студентов, отсортированный по алфавиту, и вы сортируете его по оценке. Устойчивый алгоритм сохранит алфавитный порядок среди людей с одинаковой оценкой. Неустойчивый может их «перемешать».
:::

## SelectionSort — сортировка выбором

**Идея:** найти наименьший элемент и поставить его первым. Потом найти наименьший из оставшихся и поставить вторым. И так далее.

:::analogy
Раскладываете карты на столе: просматриваете все, берёте наименьшую и кладёте первой. Из оставшихся снова выбираете наименьшую — и так до конца.
:::

```pseudo title="SelectionSort (лекция)"
Algorytm SelectionSort(a, n)
{
  for i := 0 to n-2 do {
    min := i;
    for j := i+1 to n-1 do
      if a[j] < a[min] then
        min := j;
    x := a[min];  a[min] := a[i];  a[i] := x;     // обмен
  }
}
```

**Пример** для `[29, 10, 14, 37, 13]` (зелёным — уже отсортированная часть, жёлтым — найденный минимум):

```array
@idx
старт: 29 [10] 14 37 13
проход 0: {10} 29 14 37 [13]
проход 1: {10} {13} [14] 37 29
проход 2: {10} {13} {14} 37 [29]
проход 3: {10} {13} {14} {29} {37}
```

### Анализ SelectionSort

На проходе i сравниваем a[min] с элементами i+1…n−1, то есть делаем n − 1 − i сравнений. Всего:

- **W(n) = A(n) = (n−1) + (n−2) + … + 1 = n(n−1)/2 = ½n² + O(n)** — всегда одинаково, независимо от данных,
- **Δ(n) = δ(n) = 0** — алгоритм полностью предсказуем,
- **S(n) = O(1)** — сортирует на месте.

Достоинства, названные на лекции:

1. **оптимален по числу перестановок** — всего n − 1 обменов (полезно, когда перемещение дорогое, например большие записи),
2. прост в написании,
3. достаточно быстр при малых n.

:::warn
SelectionSort **неустойчив**. Пример: `[2ᵃ, 2ᵇ, 1]` — на первом проходе 2ᵃ меняется с 1 и оказывается за 2ᵇ: `[1, 2ᵇ, 2ᵃ]`.
:::

## InsertionSort — сортировка вставками

**Идея:** в начале массива держим **отсортированный фрагмент**. Берём следующий элемент и **вставляем** его на нужное место этого фрагмента, сдвигая большие элементы на одну позицию вправо.

:::analogy
Так раскладывают карты в руке во время раздачи: каждую новую карту вставляют между уже разложенными, чтобы всё шло по порядку.
:::

```pseudo title="InsertionSort (лекция)"
Algorytm InsertionSort(a, n)
{
  for i := 1 to n-1 do {
    j := i;
    x := a[i];
    while (j > 0) AND (a[j-1] > x) do {
      a[j] := a[j-1];          // сдвигаем больший элемент вправо
      j := j - 1;
    }
    a[j] := x;                 // ставим x на освободившееся место
  }
}
```

**Пример** для `[29, 10, 14, 37, 13]` (жёлтым — вставленный элемент на новом месте):

```array
@idx
старт: 29 10 14 37 13
i=1: [10] 29 14 37 13
i=2: 10 [14] 29 37 13
i=3: 10 14 29 [37] 13
i=4: 10 [13] 14 29 37
```

### Анализ InsertionSort

Число сравнений на шаге i зависит от того, как далеко нужно сдвинуть `x`:

- **в лучшем случае** (массив уже отсортирован): 1 сравнение на шаг → **n − 1** сравнений,
- **в худшем случае** (массив отсортирован наоборот): i сравнений на шаге i → **W(n) = n(n−1)/2**,
- **в среднем:** x проходит в среднем половину отсортированного фрагмента → **A(n) ≈ n²/4**,
- **S(n) = O(1)**, алгоритм **устойчив** (сдвигаем только элементы, **строго** большие x).

:::tip
Число сдвигов в InsertionSort равно **числу инверсий** в последовательности, то есть пар (i < j) с a[i] > a[j]. Поэтому алгоритм очень быстр на **почти отсортированных** данных — на практике его часто используют, чтобы «добить» маленькие фрагменты в более быстрых алгоритмах.
:::

### InsertionSort как «разделяй и властвуй»

Лекция «Dziel i rządź» показывает тот же алгоритм рекурсивно: делим задачу на **1 и n−1** элементов. Рекурсивно сортируем первые n−1 элементов, а затем **сливаем** результат с последним элементом (то есть вставляем его на место).

- T(1) = 0, T(n) = T(n − 1) + (n − 1) ⇒ T(n) = n(n−1)/2 = O(n²).

## Сравнение

| | SelectionSort | InsertionSort |
|---|---|---|
| сравнения — лучший случай | n(n−1)/2 | n − 1 |
| сравнения — в среднем | n(n−1)/2 | ≈ n²/4 |
| сравнения — худший случай | n(n−1)/2 | n(n−1)/2 |
| перемещения | n − 1 обменов | = число инверсий (до n²/2) |
| память S(n) | O(1) | O(1) |
| устойчивый | нет | да |
| когда хорош | дорогие перемещения, малые n | почти отсортированные данные, малые n |

Оба **квадратичные** — для больших n слишком медленны. В следующих темах познакомимся с сортировками O(n log n) (MergeSort, QuickSort, HeapSort) и узнаем, что **быстрее чем n log n сравнений нельзя** (деревья решений).

## Версия лекции 2026/2027 (M. Sydow) — «Sortowanie 1» (сортировка 1)

:::exam
На тестах действуют версии **selectionSort** и **insertionSort** со слайдов ниже (массивы с 0, счётчик `next`, условие `temp < arr[curr - 1]`). Вопросы со слайдов: идея, работа, **код** и анализ каждого алгоритма.
:::

:::def Задача сортировки
- **Input:** S — последовательность элементов, которые можно упорядочить отношением линейного порядка ≤_R (например, натуральные числа); len — её длина (натуральное число).
- **Output:** S' — последовательность из тех же элементов, что и S, упорядоченная **по неубыванию** (∀ 0 < i < len: S[i−1] ≤_R S[i]).
:::

В курсе для простоты сортируем натуральные числа — кроме CountSort, на алгоритмы это не влияет. Сортировка ускоряет поиск и операции над базами данных, помогает визуализации и подсчёту статистик.

**Selection Sort** — находим минимум, меняем его с первым элементом и повторяем на последовательности со следующего индекса, пока в текущей последовательности больше 1 элемента.

```pseudo
selectionSort(S, len){
  i = 0
  while(i < len){
    mini = indexOfMin(S, i, len)
    swap(S, i, mini)
    i++
  }
}
```

`indexOfMin(S, i, len)` возвращает индекс минимума среди S[j], i ≤ j < len; `swap(S, i, mini)` меняет местами S[i] и S[mini]. **Анализ:** доминирующая операция — сравнение 2 элементов; размер данных — len. В i-й итерации ищем минимум в последовательности длины len − i: $W(len)=\sum_{i=1}^{len-1} i=\frac{len(len-1)}{2}=\Theta(len^2)$. $A(len)=W(len)$ — алгоритм всегда делает одинаковое число сравнений, **даже на уже отсортированной последовательности**.

**Insertion Sort** — начиная со второй позиции (`next`), «проталкиваем» текущий элемент назад (сравнивая), пока он не найдёт своё место и первые next + 1 элементов не будут отсортированы.

```pseudo
insertionSort(arr, len){

  for(next = 1; next < len; next++){

    curr = next;
    temp = arr[next];

    while((curr > 0) && (temp < arr[curr - 1])){

      arr[curr] = arr[curr - 1];
      curr--;
    }

    arr[curr] = temp;
  }
}
```

Инвариант внешнего цикла — аналогичный SelectionSort (начальный фрагмент отсортирован). **Худший случай:** данные **отсортированы в обратном порядке**: $W(n)=\frac{n(n-1)}{2}=\frac{1}{2}n^2+\Theta(n)=\Theta(n^2)$. Для **уже отсортированных** данных хватает **n − 1** сравнений — алгоритм «**подстраивает объём работы**» под степень отсортированности. **В среднем** (все перестановки 1..n равновероятны) в i-й итерации в среднем $\frac{1}{i}\sum_{j=1}^{i} j=\frac{i+1}{2}$ сравнений, всего $A(n)=\sum_{i=1}^{n-1}\frac{i+1}{2}=\frac{1}{4}n^2+\Theta(n)=\Theta(n^2)$ — в 2 раза быстрее SelectionSort, но всё ещё квадратично (данных в 3 раза больше → примерно в 9 раз дольше).

Квадратичная сложность слишком высока для больших данных — например, миллиард чисел — это всего 8 ГБ в RAM. Решение: **MergeSort** ([тема 6](topic:t06)).

## Selection sort

Найти минимум неотсортированной части и поменять с её первым элементом (`indexOfMin` + `swap`), `i++`.

## Insertion sort

«Проталкивать» `arr[next]` влево, пока `temp < arr[curr-1]`; первые `next+1` элементов отсортированы.

```pseudo
for(next = 1; next < len; next++){
  curr = next; temp = arr[next];
  while((curr > 0) && (temp < arr[curr - 1])){
    arr[curr] = arr[curr - 1]; curr--;
  }
  arr[curr] = temp;
}
```

## Сложности (операция: сравнение)

| | W | A | лучший | память | устойчив |
|---|---|---|---|---|---|
| Selection | $\frac{n(n-1)}{2}$ | $=W$ | $=W$ (даже для отсортированных) | $O(1)$ | нет |
| Insertion | $\frac{n(n-1)}{2}$ (обратно отсорт.) | $\frac14 n^2+\Theta(n)$ | $n-1$ (отсортированные) | $O(1)$ | да |

:::tip Запомните
Insertion «подстраивает объём работы» под степень отсортированности; в среднем в 2 раза быстрее Selection, но всё равно $\Theta(n^2)$.
:::

:::warn Типичные ошибки
- в insertion считайте и сравнение, которое **останавливает** сдвиг,
- selection делает обмен, даже если минимум уже на месте (массив не меняется).
:::
