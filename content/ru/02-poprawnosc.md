## Зачем доказывать корректность?

Обычно программу проверяют так: пишут, запускают на нескольких примерах, исправляют ошибки. Лекция называет три недостатка этого метода:

1. Иногда тестировать на настоящих данных **невозможно** (например, ПО ракеты — тест «одноразовый»).
2. Ошибки, найденные после тестов, **дорогие** — чем позже найдена ошибка, тем больше она стоит.
3. **Тестирование может показать, что ошибка есть, но никогда — что её нет.** Невозможно проверить все возможные данные.

Поэтому мы учимся **доказывать**, что алгоритм корректен, — так же, как в математике доказывают теоремы.

## Спецификация: что алгоритм получает и что должен вернуть

Прежде чем сказать «алгоритм корректен», нужно сказать — **относительно чего**. Это «что» — **спецификация**:

:::def
- **Предусловие** (входное условие, *warunek początkowy*) **α** — что мы предполагаем о входных данных (например, «n > 0», «массив отсортирован»).
- **Постусловие** (выходное условие, *warunek końcowy*) **β** — что должно быть истинно после завершения алгоритма (например, «результат = наибольший элемент массива»).
- Запись **{α} K {β}** читается: «если данные удовлетворяют α и алгоритм K завершится, то результаты удовлетворяют β».
:::

Пример: для `Max_w_tablicy(A, n)` из темы 1:

- α: `n > 0`, `A` — массив из n целых чисел,
- β: результат является элементом `A` и ≥ каждого элемента `A`.

:::warn
Предусловие — не формальность. При `n = 0` алгоритм Max обратился бы к несуществующему `A[0]`. Спецификация честно говорит: «для таких данных я ничего не обещаю».
:::

## Три свойства: частичная корректность, определённость, остановка

Лекция различает три вещи, которые мы хотим доказать:

1. **Частичная корректность** (*częściowa poprawność*) — если данные удовлетворяют α и вычисление **дойдёт до конца**, то результаты удовлетворяют β.
2. **Определённость вычислений** (*określoność*) — для данных, удовлетворяющих α, вычисление **не прервётся** ошибкой (деление на 0, выход за пределы массива).
3. **Свойство остановки** (*własność stopu*) — для данных, удовлетворяющих α, вычисление **не бесконечно** (циклы заканчиваются).

:::def
Алгоритм **полностью корректен** (*całkowicie poprawny*) относительно α и β, если он **частично корректен** и обладает **свойством остановки** (а вычисления определены). Иначе говоря: для любых правильных данных он **остановится** и выдаст **правильный результат**.
:::

:::analogy
Автонавигатор *частично корректен*, если каждый раз, когда он вас куда-то довёз, это правильный адрес. Но он может и… никогда не доехать, кружа по кольцу. Он *полностью корректен*, когда **всегда доезжает** и **всегда по правильному адресу**.
:::

## Метод инвариантов

Простые алгоритмы без циклов легко проверить «на глаз». Сложность — в **циклах**: заранее неизвестно, сколько раз они выполнятся. Для циклов есть отличный инструмент — **инвариант**.

:::def
**Инвариант цикла** (*niezmiennik*) — условие g, которое истинно **каждый раз**, когда управление доходит до проверки условия цикла: перед первой итерацией и после каждой следующей.
:::

Чтобы показать частичную корректность цикла `{α} while W do K {β}`, достаточно показать **три вещи**:

1. **Инициализация:** α ⇒ g — инвариант истинен в начале.
2. **Сохранение:** {g ∧ W} K {g} — если g истинно и мы входим в цикл (W истинно), то после одной итерации g по-прежнему истинно.
3. **Завершение:** g ∧ ¬W ⇒ β — когда цикл заканчивается (W ложно), инвариант вместе с отрицанием условия даёт β.

:::analogy
Это как доказательство по индукции про лестницу: (1) вы стоите на первой ступеньке, (2) с любой ступеньки умеете подняться на следующую, значит (3) когда лестница закончится, вы наверху. Инвариант — это фраза «я уверенно стою на лестнице», истинная на каждой ступеньке.
:::

### Как придумать инвариант?

Инвариант обычно говорит: **«то, что я уже сделал, сделано правильно»**. Для цикла по массиву: «результат для уже просмотренной части массива верен». В конце «просмотренная часть» = весь массив, значит, результат верен для всего.

### Пример 1: максимум в массиве

```pseudo title="Max_w_tablicy с инвариантом"
Algorytm Max_w_tablicy(A, n):
{
  // n > 0; A - массив целых чисел
  dotychczas_naj := A[0];
  for i := 1 to n-1 do
    // Инв.: dotychczas_naj = MAX(A[0..i-1])
    if dotychczas_naj < A[i] then
      dotychczas_naj := A[i];
  // dotychczas_naj = MAX(A[0..n-1])
  return dotychczas_naj
}
```

1. **Начало:** перед первой итерацией i = 1 и `dotychczas_naj = A[0] = MAX(A[0..0])` ✓.
2. **Итерация:** если `dotychczas_naj = MAX(A[0..i−1])`, то после сравнения с `A[i]` получаем `MAX(A[0..i])` — и увеличиваем i ✓.
3. **Конец:** цикл заканчивается при i = n, значит `dotychczas_naj = MAX(A[0..n−1])` ✓.

Остановка: цикл `for` выполняется ровно n − 1 раз.

### Пример 2: целочисленный квадратный корень — линейная версия

Для n ≥ 0 ищем ⌊√n⌋, то есть **наибольшее** p, для которого p² ≤ n. Эквивалентно:

> p = ⌊√n⌋ ⇔ (p · p ≤ n) ∧ ((p + 1) · (p + 1) > n)

```pseudo title="sqrt — линейная версия"
Algorytm sqrt(n):
  Dane:  неотрицательное целое n
  Wynik: целая часть квадратного корня из n
{
  p := 0;
  while (p+1)*(p+1) <= n do
    // Инв.: p*p <= n
    p := p + 1;
  // p = [sqrt(n)]
  return p
}
```

- **Начало:** p = 0 и n ≥ 0, значит p² ≤ n ✓.
- **Итерация:** входим в цикл только при (p+1)² ≤ n; после `p := p+1` снова p² ≤ n ✓.
- **Конец:** цикл заканчивается, когда (p+1)² > n. Вместе с инвариантом p² ≤ n это в точности определение p = ⌊√n⌋ ✓.
- **Остановка:** p растёт на 1 за итерацию, а (p+1)² ≤ n не может быть истинным бесконечно.

### Пример 3: корень быстрее — деление отрезка пополам

Линейная версия делает около √n итераций. Лекция показывает версию с **бинарным поиском**: держим отрезок [l, r], в котором точно есть ответ, и каждый раз делим его пополам.

```pseudo title="sqrt — версия с бинарным поиском"
Algorytm sqrt(n):
{
  l := 0;  r := n;           // левый и правый концы отрезка
  while l < r do
  // Инв.: l*l <= n  &  (r+1)*(r+1) > n  &  l <= r
  {
    s := [(l + r) / 2];      // целая часть среднего
    if (s+1)*(s+1) <= n then
      l := s + 1             // корень > s
    else
      r := s;                // корень <= s
  }
  // l = [sqrt(n)]
  return l
}
```

Доказательство по трём шагам:

1. **Начало:** l = 0 даёт l² = 0 ≤ n. При r = n: (n+1)² = n² + 2n + 1 > n. Также l ≤ r ✓.
2. **Итерация:** если (s+1)² ≤ n, то после `l := s+1` по-прежнему l² ≤ n. Если (s+1)² > n, то после `r := s` по-прежнему (r+1)² > n. Так как l ≤ s < r, условие l ≤ r тоже сохраняется ✓.
3. **Конец:** ¬(l < r) и l ≤ r дают **l = r**. Тогда l² ≤ n и (l+1)² > n, то есть l = ⌊√n⌋ ✓.

**Остановка — убывающая функция.** Рассмотрим f = r − l. Это натуральное число, и на каждой итерации оно **строго уменьшается** (так как l ≤ s < r: либо l растёт до s + 1 > l, либо r падает до s < r). Последовательность натуральных чисел не может убывать бесконечно, значит цикл закончится.

:::def
**Убывающая функция** (мера прогресса, *funkcja malejąca*) — выражение с натуральными значениями, которое **строго уменьшается** на каждой итерации цикла. Её существование доказывает **свойство остановки**.
:::

:::exam
Типичная задача на занятиях: «определите пред- и постусловия, докажите свойство остановки, укажите и докажите инвариант, докажите частичную и полную корректность». Схема ответа всегда одна и та же:
1. α и β,
2. убывающая функция → **остановка**,
3. инвариант: начало / итерация / конец → **частичная корректность**,
4. остановка + частичная = **полная корректность**.
:::

## Рецепт для задач на корректность {own}

:::own
Эта схема — итог от автора сайта; пригодится в любой задаче «докажите полную корректность».

1. **Назовите начальные значения.** Если алгоритм меняет параметры (например, `n := n − 1`), запишите их начальные значения как N, X, Y… — инварианту они часто нужны.
2. **Запишите, что верно «на полпути».** Выпишите значения переменных после 0, 1, 2, 3 итераций на маленьком примере и ищите соотношение, которое не меняется (например, `s = i · x`, `r + x·y = X·Y`).
3. **Проверьте три шага** (начало / итерация / конец). Для «итерации» разберите каждую ветку `if` отдельно.
4. **Найдите убывающую функцию** (например, `n − i`, `y`, `r − l`) — она должна быть натуральной и строго убывать.
5. **Оцените сложность:** сколько раз максимум может уменьшиться убывающая функция?

=== summary ===

## Определения

- **Спецификация:** предусловие **α** (о данных) и постусловие **β** (о результатах); запись **{α} K {β}**.
- **Частичная корректность:** если α и алгоритм завершился ⇒ β.
- **Определённость:** нет ошибок выполнения (деление на 0, неверный индекс).
- **Свойство остановки:** для данных, удовлетворяющих α, алгоритм останавливается.
- **Полная корректность** = частичная корректность + остановка.

## Метод инвариантов (цикл `while W do K`)

1. **Начало:** α ⇒ g
2. **Итерация:** {g ∧ W} K {g}
3. **Конец:** g ∧ ¬W ⇒ β

**Остановка:** убывающая функция — натуральное значение, строго убывает на каждой итерации.

## Примеры с лекции

| Алгоритм | Инвариант | Убывающая функция |
|---|---|---|
| Максимум в массиве | `best = MAX(A[0..i−1])` | n − i |
| линейный sqrt | p² ≤ n | n − p² (или ⌊√n⌋ − p) |
| бинарный sqrt | l² ≤ n ∧ (r+1)² > n ∧ l ≤ r | r − l |

- p = ⌊√n⌋ ⇔ p² ≤ n < (p+1)².
- линейный sqrt: ~√n итераций; бинарный: ~log₂ n итераций.

## Схема ответа на занятиях

α, β → убывающая функция (остановка) → инвариант (начало/итерация/конец) → полная корректность → сложность (сколько раз убывает убывающая функция).

**a)** `Min(T, n)`; α: n ≥ 1, T[0..n−1] — целые; β: результат m — один из элементов T и m ≤ T[j] для каждого j.

```pseudo
Algorytm Min(T, n):
{
  m := T[0];
  for i := 1 to n-1 do
    if T[i] < m then m := T[i];
  return m
}
```
**b)** `Product(T, n)`; α: n ≥ 0; β: результат = T[0]·T[1]·…·T[n−1] (при n = 0 результат = 1).
```pseudo
Algorytm Product(T, n):
{
  p := 1;
  for i := 0 to n-1 do p := p * T[i];
  return p
}
```
**c)** `CountEven(T, n)`; α: n ≥ 0; β: результат = количество индексов i, для которых T[i] mod 2 = 0.
```pseudo
Algorytm CountEven(T, n):
{
  c := 0;
  for i := 0 to n-1 do
    if T[i] mod 2 = 0 then c := c + 1;
  return c
}
```
:::

:::task level=1 source="Ćwiczenie 2, зад. 2 (изменено)" title="Что верно после цикла?"
Рассмотрим фрагмент:
```pseudo
a := 10;
b := 0;
while a > 3 do {
  a := a - 1;
  b := b + 2;
}
// покажите, что здесь b = 14
```
Покажите (через инвариант, а не просто «пересчётом»), что после цикла `b = 14`.
::hint
Посмотрите, как a и b меняются вместе: когда a уменьшается на 1, b растёт на 2. Что при этом не меняется?
::solution
**Инвариант:** g ≡ (b = 2·(10 − a)) ∧ (a ≥ 3).

1. **Начало:** a = 10, b = 0: 0 = 2·(10 − 10) ✓, 10 ≥ 3 ✓.
2. **Итерация:** пусть g и a > 3. После `a := a − 1`, `b := b + 2` имеем b + 2 = 2·(10 − a) + 2 = 2·(10 − (a − 1)) ✓, а новое a = a − 1 ≥ 3, так как a > 3 ✓.
3. **Конец:** ¬(a > 3) даёт a ≤ 3, а из g: a ≥ 3, значит a = 3 и b = 2·(10 − 3) = **14** ✓.

**Остановка:** убывающая функция a − 3 ≥ 0 уменьшается на 1 за итерацию (7 итераций).
:::

:::task level=2 source="Ćwiczenie 2, зад. 3 (изменено)" title="Умножение через сложение"
```pseudo
Algorytm mult(x, n):
{
  i := 0;
  s := 0;
  while i < n do {
    s := s + x;
    i := i + 1;
  }
  return s
}
```
a) Определите пред- и постусловия.
b) Докажите свойство остановки.
c) Укажите и докажите инвариант цикла.
d) Докажите частичную и полную корректность.
::hint
После k итераций i = k, а s — это x, сложенное k раз.
::solution
a) α: x — целое, n — целое, **n ≥ 0**. β: результат = x · n.

b) **Остановка:** f = n − i. В начале f = n ≥ 0; на каждой итерации i растёт на 1, значит f уменьшается на 1; цикл работает только при f > 0. После n итераций f = 0, и цикл заканчивается.

c) **Инвариант:** g ≡ (s = i · x) ∧ (0 ≤ i ≤ n).
- начало: i = 0, s = 0 = 0·x, 0 ≤ 0 ≤ n ✓;
- итерация: из g и i < n: новое s = i·x + x = (i+1)·x, новое i = i + 1 ≤ n ✓.

d) **Частичная корректность:** после цикла ¬(i < n), т.е. i ≥ n; из g: i ≤ n, значит i = n и s = n·x = β ✓. **Полная корректность** = частичная + остановка (b) ✓. Сложность: ровно n сложений.
:::

:::task level=2 source="Ćwiczenie 2, зад. 4 (изменено)" title="Тот же цикл без счётчика"
Запишите алгоритм из предыдущей задачи **без переменной i** (изменяя параметр n) и проведите для него доказательство: остановка, инвариант, частичная и полная корректность.
::hint
Обозначьте начальное значение n через N. Инвариант должен связывать «сколько я уже прибавил» и «сколько ещё осталось».
::solution
```pseudo
Algorytm mult2(x, n):
{
  // N = начальное значение n, N >= 0
  s := 0;
  while n > 0 do {
    s := s + x;
    n := n - 1;
  }
  return s
}
```
- **Остановка:** f = n ≥ 0 уменьшается на 1 за итерацию.
- **Инвариант:** g ≡ (s + n·x = N·x) ∧ (n ≥ 0).
  - начало: s = 0, n = N: 0 + N·x = N·x ✓;
  - итерация: (s + x) + (n − 1)·x = s + n·x = N·x ✓, а новое n = n − 1 ≥ 0, так как n > 0 ✓.
- **Конец:** ¬(n > 0) ∧ n ≥ 0 ⇒ n = 0, значит s = N·x ✓.
- Полная корректность = частичная + остановка ✓.
:::

Ищите инвариант вида «r + (что-то из x и y) = X·Y». Разберите отдельно чётное y (y = 2k) и нечётное (y = 2k + 1).
::solution
**Инвариант:** g ≡ (r + x·y = X·Y) ∧ (y ≥ 0).

- **Начало:** r = 0, x = X, y = Y ⇒ 0 + X·Y ✓.
- **Итерация, y = 2k (чётное):** r не меняется, новое y = k, новое x = 2x: r + 2x·k = r + x·y ✓.
- **Итерация, y = 2k + 1 (нечётное):** новое r = r + x, y = k, x = 2x: (r + x) + 2x·k = r + x(2k+1) = r + x·y ✓.
- **Конец:** y = 0 ⇒ r = X·Y ✓.
- **Остановка:** убывающая функция y: при y > 0 имеем y div 2 < y, значения натуральные ⇒ цикл закончится.

**Сложность:** y делится на 2 на каждой итерации, поэтому число итераций равно числу битов Y: **⌊log₂ Y⌋ + 1** (при Y > 0). Относительно размера данных (числа битов) — линейно.

**Выполнение `mul(13, 11)`:**

| итерация | x | y | r | комментарий |
|---|---|---|---|---|
| начало | 13 | 11 | 0 | |
| 1 | 26 | 5 | 13 | 11 нечётное → r += 13 |
| 2 | 52 | 2 | 39 | 5 нечётное → r += 26 |
| 3 | 104 | 1 | 39 | 2 чётное |
| 4 | 208 | 0 | 143 | 1 нечётное → r += 104 |

Результат 143 = 13·11 ✓, 4 итерации = число битов 11 (1011₂) ✓.
:::

:::task level=3 source="Ćwiczenie 2a / 3, зад. 2 (изменено)" title="Робот и шары в коробках"
На полке стоят n коробок с номерами 0…n−1, в каждой один шар: **зелёный** или **жёлтый**. Робот умеет:
- `Color(i)` — открыть коробку i и сказать цвет шара (это **дорого**, поэтому хотим делать это как можно реже),
- `Swap(i, j)` — поменять коробки местами (внимание: при i = j робот ломается!).

Цель: все зелёные слева, все жёлтые справа.

```pseudo
l := 0;  r := n - 1;
while l < r do
  if Color(l) = ЗЕЛЁНЫЙ then
    l := l + 1
  else {
    Swap(l, r);
    r := r - 1
  }
```
Докажите полную корректность. Сколько раз будет вызвана `Color` и сколько раз `Swap` (худший случай)? Может ли робот сломаться?
::hint
Нарисуйте полку как три зоны: [0..l−1] — уже известно, что зелёные; [r+1..n−1] — уже известно, что жёлтые; середина — неизвестна.
::solution
**Инвариант:** g ≡ во всех коробках 0..l−1 зелёные шары ∧ во всех коробках r+1..n−1 жёлтые шары ∧ 0 ≤ l ≤ r + 1 ≤ n.

- **Начало:** l = 0, r = n − 1 — обе зоны пусты, значит g истинно ✓.
- **Итерация (в l зелёный):** l := l + 1 — зелёная зона увеличивается на коробку с зелёным шаром ✓.
- **Итерация (в l жёлтый):** после `Swap(l, r)` жёлтый шар в коробке r, и после r := r − 1 жёлтая зона растёт на жёлтую коробку ✓. (Мы не знаем, что попало на позицию l, поэтому l не увеличиваем.)
- **Конец:** ¬(l < r) и l ≤ r + 1 ⇒ l = r или l = r + 1. В неизвестной зоне ≤ 1 коробки, а одна коробка не «портит» разбиение — все зелёные слева, жёлтые справа ✓.
- **Остановка:** f = r − l уменьшается на 1 за итерацию (растёт l или уменьшается r) ✓.

**Сложность:** r − l начинается с n − 1 и уменьшается на 1 за итерацию, поэтому при n ≥ 1 будет **ровно n − 1 итераций** ⇒ **n − 1 вызовов `Color`** (оптимум для этого метода). `Swap` — не более **n − 1** (когда все шары жёлтые).

**Может ли робот сломаться?** Нет: `Swap(l, r)` вызывается только внутри цикла, когда l < r, значит всегда l ≠ r.

:::own
Замечание автора: алгоритм иногда меняет жёлтый с жёлтым (впустую). Это можно улучшить, проверяя цвет и в r, — но тогда растёт число дорогих вызовов `Color`. Здесь мы оптимизируем число `Color`, так что простой алгоритм хорош.
:::
