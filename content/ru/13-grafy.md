## Что такое граф?

:::def
**Граф** — это пара **G = (V, E)**, где V — конечное множество **вершин** (узлов), а E — множество **рёбер**:
- в **неориентированном** графе ребро — неупорядоченная пара {x, y} (x ≠ y),
- в **ориентированном** — упорядоченная пара (x, y), то есть стрелка от x к y.

Ребро между x и y записываем (x, y). **Размер графа** — два числа: **n = |V|** и **m = |E|**.
:::

Для неориентированного графа **m ≤ n(n − 1)/2**, для ориентированного **m ≤ n(n − 1)**.

:::analogy
Карта городов и дорог: города — вершины, дороги — рёбра. Двусторонние дороги — неориентированный граф; улицы с односторонним движением — ориентированный. Друзья в соцсети — неориентированный граф; «подписки» — ориентированный.
:::

## Представления графа

Считаем, что V = {1, 2, …, n} — вершины являются индексами массивов.

- **Списки смежности:** для каждого x ∈ V список **L[x]** вершин y, для которых (x, y) ∈ E. Память: **O(n + m)**.
- **Матрица смежности:** A[x, y] = 1, если (x, y) — ребро, иначе 0. Память: **O(n²)**.

```graph

2 160 20

4 160 120
1-2
1-3
2-4
3-4
2-3
```

Для графа выше:

| x | L[x] |
|---|---|
| 1 | 2, 3 |
| 2 | 1, 3, 4 |
| 3 | 1, 2, 4 |
| 4 | 2, 3 |

| A | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| **1** | 0 | 1 | 1 | 0 |
| **2** | 1 | 0 | 1 | 1 |
| **3** | 1 | 1 | 0 | 1 |
| **4** | 0 | 1 | 1 | 0 |

## Общая схема обхода графа

Лекция asd11 начинает с **общей схемы**, из которой потом получаются конкретные алгоритмы. Хотим, начав с вершины p, посетить каждую вершину и каждое ребро, достижимые из p. Разрешённый ход — пройти по ребру, выходящему из **уже посещённой** вершины.

1. Посетить p и отметить её как посещённую.
2. Пока из какой-нибудь посещённой вершины выходит непосещённое ребро:
   - (a) выбрать посещённую вершину v, из которой выходит непосещённое ребро,
   - (b) выбрать любое непосещённое ребро (v, w),
   - (c) отметить его как посещённое,
   - (d) если w ещё не посещена — посетить её и отметить.

Индукцией по расстоянию от p можно доказать, что алгоритм посещает **каждую** вершину и **каждое** ребро, достижимые из p (каждую вершину ровно один раз). Сложность **пропорциональна суммарному числу вершин и рёбер** — то есть **линейна**: O(n + m).

Чтобы получить конкретный алгоритм, нужно решить:
1. как представить граф (например, списками смежности),
2. как отмечать посещённые вершины (массив `visited[v]`),
3. **как выбирать** вершину v на шаге (a) — например, храня кандидатов в **стеке** или в **очереди**,
4. как отличать посещённые рёбра от непосещённых — например, указателем **current[v]** на первое непосещённое ребро в списке L[v].

## DFS — поиск в глубину (стек)

Если кандидатов хранить в **стеке**, мы всегда берём вершину, посещённую **последней**. Поэтому идём «как можно глубже» в граф и только когда идти некуда — возвращаемся.

:::analogy
Исследование лабиринта с клубком ниток: идёте по коридору, пока можно; в тупике возвращаетесь к последней развилке, где ещё есть непройденный путь.
:::

```pseudo title="DFS (лекция)"
void DFS(graf G) {
  for (v = 1; v <= n; v++) {
    visited[v] = FALSE;
    current[v] = указатель на первый элемент списка L[v];
  }
  visit(p); visited[p] = TRUE;
  if (current[p] != NULL) {
    S = []; Push(S, p);
    while (!Empty(S)) {
      v = Front(S);                         // вершина на вершине стека
      пусть w — вершина, на которую указывает current[v];
      сдвинуть current[v] к следующей вершине списка L[v];
      if (current[v] == NULL) Pop(S);       // из v больше не выходят новые рёбра
      if (!visited[w]) {
        visit(w); visited[w] = TRUE;
        if (current[w] != NULL) Push(S, w);
      }
    }
  }
}
```

## BFS — поиск в ширину (очередь)

Если кандидатов хранить в **очереди**, мы сначала «исчерпываем» соседей вершины, посещённой **раньше всех**. Поэтому вершины посещаются **слоями**: сначала p, затем все соседи p (расстояние 1), потом их соседи (расстояние 2) и т. д.

:::analogy
Круги на воде от брошенного камня: сначала намокают ближайшие точки, потом всё более дальние кольца.
:::

В коде меняется только структура: вместо `Push` — `Inject` (добавить в конец очереди), а `Front`/`Pop` работают с началом очереди.

:::tip
**BFS находит кратчайшие пути** (по числу рёбер) от p до всех вершин: достаточно запомнить dist[w] = dist[v] + 1 в момент посещения w. Для взвешенных графов нужен алгоритм Дейкстры (тема 14).
:::

**Пример** (соседи просматриваются по алфавиту, старт в A):

```graph
A 30 70
B 130 20
C 130 120
D 230 70
E 330 70
F 430 70
A-B
A-C
B-D
C-D
D-E
E-F
```

- **DFS:** A, B, D, C, E, F — из A в B, из B в D, из D в C (тупик: A и D посещены), возврат в D, дальше E, F.
- **BFS:** A, B, C, D, E, F — слои: {A}, {B, C}, {D}, {E}, {F}; расстояния: A 0, B 1, C 1, D 2, E 3, F 4.

### Метод пошагового уточнения

Лекция подчёркивает, **как** получились процедуры DFS и BFS: мы начали с общей схемы и затем шаг за шагом **уточняли** выбор (представление, отметки, стек или очередь, указатели current). Это **метод пошагового уточнения** (*metoda kolejnych uściśleń*, stepwise refinement). В процедурах ещё осталось кое-что «доработать» (например, точную работу со списками и указателями) — окончательное преобразование в машинный код делает компилятор.

### Применения DFS и BFS {own}

:::own
Обзор применений от автора сайта — всё работает за O(n + m).
:::

- **связность:** неориентированный граф связен ⇔ один DFS/BFS посещает все вершины; число запусков DFS из непосещённых вершин = число **компонент связности**,
- **кратчайшие пути** без весов — BFS,
- **поиск циклов**, **топологическая сортировка** ориентированного ациклического графа — DFS,
- **лабиринты, игры** (например, наименьшее число ходов) — BFS.

## Структура Find-Union (непересекающиеся множества)

Слайды 2009 (лекция X) описывают структуру, нужную, в частности, в алгоритме Краскала (тема 14).

:::def
**Задача Find-Union:** элементы 1, …, n разбиты на **непересекающиеся** множества (вначале каждый элемент — отдельное множество). Операции:
- **find(x)** — вернуть имя (представителя) множества, содержащего x,
- **union(A, B)** — объединить множества A и B в одно.
:::

:::analogy
Компании друзей на вечеринке: вначале каждый стоит один. Когда двое знакомятся, их компании сливаются в одну (union). find(x) отвечает на вопрос «кто главный в компании x?» — двое в одной компании, если у них один и тот же главный.
:::

Реализации (от самой простой):

1. **Массив имён** name[x]: find — O(1), но union должен переименовать всё множество — O(n).
2. **Списки с балансировкой:** каждое множество — список; при union переименовываем **меньший** список. Элемент меняет имя, только когда его множество как минимум удваивается, — значит, не более log n раз. n − 1 операций union стоят в сумме **O(n log n)**.
3. **(n-арные) деревья с балансировкой и сжатием путей:** каждое множество — дерево, корень — представитель, каждый узел указывает на отца.
   - find(x) — идём от x до корня,
   - union — корень **более низкого** дерева подвешиваем под корень более высокого → высота деревьев ≤ log n,
   - **сжатие путей** — во время find подвешиваем все пройденные узлы **прямо под корень**; следующие find почти мгновенны.

С балансировкой и сжатием последовательность из m операций стоит **O(m · α(n))**, где α — чрезвычайно медленно растущая функция (обратная к функции Аккермана; на практике α(n) ≤ 4), — то есть **почти константное время** на операцию.

=== summary ===

## Графы

- G = (V, E), n = |V|, m = |E|; неориентированный: m ≤ n(n−1)/2, ориентированный: m ≤ n(n−1).
- **списки смежности** O(n + m) — разреженные графы; **матрица** O(n²) — плотные, проверка ребра O(1).

## Обход графа

- схема: посетить p; пока есть непосещённое ребро из посещённой v — пройти по нему; каждая вершина и ребро один раз → **O(n + m)**.
- **DFS** — кандидаты в **стеке** (вглубь, с возвратами); **BFS** — в **очереди** (слоями).
- BFS даёт кратчайшие пути (по числу рёбер): dist[w] = dist[v] + 1.
- метод **пошагового уточнения**.

## Find-Union

- find(x), union(A, B) на непересекающихся множествах.
- массив имён: union O(n); списки с балансировкой: n−1 union O(n log n); **деревья + балансировка + сжатие путей: почти O(1)** (O(m α(n))).
- применение: алгоритм Краскала, компоненты связности.

:::task level=1 source="own" title="Представление в памяти"
Неориентированный граф имеет **n = 1000** вершин и **m = 3000** рёбер. Сколько ячеек займёт матрица смежности и сколько элементов суммарно во всех списках смежности? Каково максимально возможное число рёбер этого графа?
::hint
В неориентированном графе каждое ребро появляется в двух списках.
::solution
- матрица: n² = **1 000 000** ячеек,
- списки: каждое ребро в двух списках → 2m = **6000** элементов (+ 1000 начал списков),
- максимальное число рёбер: n(n − 1)/2 = **499 500**.

У графа лишь 3000 из 499 500 возможных рёбер — он **разреженный**, поэтому списки намного лучше.
:::

:::task level=2 source="own" title="Компоненты связности"
У графа вершины 1…9 и рёбра: {1,2}, {2,3}, {4,5}, {6,7}, {7,8}, {8,6}. Сколько у него компонент связности? Опишите, как найти их с помощью DFS и сколько раз его придётся запустить.
::hint
Пройдите циклом по всем вершинам; для каждой ещё не посещённой запустите DFS.
::solution
Компоненты: {1, 2, 3}, {4, 5}, {6, 7, 8}, {9} → **4 компоненты**.

Алгоритм: `for v := 1 to n do if not visited[v] then { счётчик++; DFS(v) }`. DFS запустится **4 раза** (для 1, 4, 6, 9), а общая стоимость O(n + m), так как каждая вершина и ребро посещаются один раз.
:::

:::task level=3 source="own" title="Find-Union с балансировкой и сжатием"
Есть элементы 1…8, каждый в отдельном множестве. Выполните по очереди: union(1,2), union(3,4), union(5,6), union(7,8), union(1,3), union(5,7), union(1,5), а затем find(8). При union подвешивайте корень более низкого дерева под корень более высокого (при равных высотах — второй под первый), а find выполняйте со сжатием пути. Нарисуйте дерево до и после find(8).
::hint
После первых четырёх union — четыре дерева высоты 1. После union(1,3) и union(5,7) — два дерева высоты 2.
::solution
- union(1,2): 2 под 1; union(3,4): 4 под 3; union(5,6): 6 под 5; union(7,8): 8 под 7.
- union(1,3): высоты равны → 3 под 1; union(5,7): 7 под 5.
- union(1,5): высоты равны (2) → 5 под 1. Высота дерева = 3.

```tree caption="до find(8)"
1(2,3(4,_),5(6,7(8,_)))
```

Внимание: это **n-арное** дерево — у узла 1 три сына (2, 3, 5).

find(8) идёт по пути 8 → 7 → 5 → 1 и возвращает **1**. Сжатие: 8 и 7 подвешиваются прямо под 1.

```text title="после find(8): отцы узлов"
узел:  1  2  3  4  5  6  7  8
отец:  1  1  1  3  1  5  1  1
```
:::
