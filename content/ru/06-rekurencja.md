## Что такое рекурсия?

:::def
Функция (метод) **рекурсивна**, если она вызывает **сама себя** — напрямую или косвенно (через другие функции).
:::

Рекурсия часто даёт гораздо **более короткие и понятные** алгоритмы, чем версия без неё. У каждой корректной рекурсивной функции две части:

1. **базовый случай** — настолько маленькие данные, что результат известен сразу (без рекурсии),
2. **рекурсивный шаг** — сводим задачу к **меньшей** задаче того же типа.

:::analogy
Матрёшка: чтобы увидеть самую маленькую, открываете большую, внутри — поменьше, с ней делаете **то же самое**. Останавливаетесь на матрёшке, которая не открывается (базовый случай).
:::

:::warn
Нет базового случая (или шаг **не уменьшает** задачу) = бесконечная рекурсия и ошибка `StackOverflowError`.
:::

### Как компьютер выполняет рекурсию? Стек вызовов

Лекция asd6 подчёркивает: каждый вызов работает со **своими локальными копиями** параметров и переменных. После возврата из рекурсивного вызова нужно продолжить вычисления с **прежними** значениями — значит, их надо где-то хранить. Такая структура — **стек** (подробнее в теме 9): каждый вызов кладёт на стек свои данные и снимает их по завершении.

## Пример 1: число в двоичной системе

**Задача:** вывести целое x > 0 в двоичной системе.

Последняя двоичная цифра — `x % 2`. Остальные цифры — двоичная запись числа `x / 2`. Их нужно вывести **перед** последней цифрой — поэтому сначала рекурсия, и только потом печать.

```text title="Вызовы для x = 27"
dwojkowy(27): цифра = 1, вызов dwojkowy(13)
  dwojkowy(13): цифра = 1, вызов dwojkowy(6)
    dwojkowy(6): цифра = 0, вызов dwojkowy(3)
      dwojkowy(3): цифра = 1, вызов dwojkowy(1)
        dwojkowy(1): цифра = 1  (x/2 = 0 — конец рекурсии)
        печать 1
      печать 1
    печать 0
  печать 1
печать 1                             → 11011
```

Заметьте: цифры печатаются «на обратном пути» — начиная с самого глубокого вызова.

## Пример 2: Ханойские башни

Есть три стержня A, B, C. На стержне A лежат n колец разного диаметра — от самого большого внизу до самого маленького наверху. Нужно перенести все кольца на стержень C по правилам:

- за один ход переносим **только одно** (верхнее) кольцо,
- **никогда** не кладём большее кольцо на меньшее,
- стержень B можно использовать как вспомогательный.

**Рекурсивное решение** (удивительно простое): чтобы перенести n колец с A на C:

1. перенести (рекурсивно) **n − 1** верхних колец с A на **B** (через C),
2. перенести **самое большое** кольцо с A на C,
3. перенести (рекурсивно) **n − 1** колец с B на **C** (через A).

```text title="Ходы для n = 3 (с A на C)"
A->C  A->B  C->B  A->C  B->A  B->C  A->C      (7 ходов)
```

### Сколько ходов? {own}

:::own
Вывода формулы на слайдах не было, но он часто встречается на занятиях.
:::

Пусть H(n) — число ходов. Из описания: H(0) = 0, **H(n) = 2·H(n − 1) + 1**. По очереди: 1, 3, 7, 15, 31, … то есть **H(n) = 2ⁿ − 1** (индукция: 2·(2ⁿ⁻¹ − 1) + 1 = 2ⁿ − 1). Это **экспоненциальная** сложность — и лучше нельзя (самое большое кольцо обязано сдвинуться, а до этого все остальные должны «уйти с дороги»). Для 64 колец: 2⁶⁴ − 1 ≈ 1,8·10¹⁹ ходов.

## Пример 3: генерация всех перестановок

Со слайдов 2009: вывести все перестановки элементов массива. Идея: на последнюю позицию (k − 1) по очереди ставим каждый элемент, а остальные k − 1 позиций переставляем рекурсивно.

```text title="Вывод для [1, 2, 3] (порядок генерации)"
231  321  312  132  213  123
```

- число выведенных перестановок: **n!**,
- временная сложность: **Θ(n!)** (не меньше, чем результатов нужно вывести),
- дополнительная память: глубина рекурсии n, то есть **O(n)**.

## Принцип «разделяй и властвуй»

Древние римляне говорили *divide et impera* — легче править, когда подданные разделены. В программировании мы делаем это «гуманнее»:

:::def
**Разделяй и властвуй** (*dziel i rządź*):
1. умеем решить задачу для **маленьких** данных (базовый случай),
2. большие данные **делим** так, чтобы свести задачу к нескольким **меньшим** подзадачам,
3. решаем подзадачи (обычно рекурсивно),
4. **объединяем** их результаты в решение всей задачи.
:::

Примеры мы уже знаем:

| Алгоритм | Разбиение | Объединение |
|---|---|---|
| min и max (тема 4) | пополам | 2 сравнения |
| рекурсивный InsertionSort (тема 5) | 1 ; n−1 | вставка элемента |
| **MergeSort** | пополам | слияние последовательностей — линейно |
| QuickSort (тема 7) | относительно опорного | ничего (всю работу делает разбиение) |

## MergeSort — сортировка слиянием

**Идея:** делим последовательность на две **половины**, сортируем каждую (рекурсивно), а затем **сливаем** две отсортированные последовательности в одну.

:::analogy
Перед вами две отсортированные колоды карт лицом вверх, самые маленькие сверху. Сравниваете две верхние карты и меньшую кладёте в итоговую стопку. Повторяете, пока одна колода не кончится, — остаток другой кладёте в конец. Так работает слияние.
:::

### Слияние

Есть отсортированные фрагменты `c[l..s]` и `c[s+1..p]`. Держим указатель i в первом, j во втором и каждый раз переписываем **меньший** из `c[i]`, `c[j]` во вспомогательный массив `b`.

- **Инвариант:** `b[l..k]` = слитые `c[l..i−1]` и `c[s+1..j−1]` (отсортировано).
- Слияние последовательностей длины p и q требует **не более p + q − 1** сравнений.

```array
левая: {3} 27 38 43
правая: {9} 10 82
b: 3 _ _ _ _ _ _
b: 3 9 10 27 38 43 82
```

### Алгоритм

```pseudo title="MergeSort (лекция)"
Algorytm MergeSort(c, n)
{
  if n > 1 then Sortuj(0, n-1)
}

Sortuj(l, p):              // сортирует c[l..p]
{
  if l < p then {
    s := (l + p) div 2;
    Sortuj(l, s);
    Sortuj(s+1, p);
    Scal(l, s, p);          // сливает c[l..s] с c[s+1..p]
  }
}
```

**Пример** для `[38, 27, 43, 3, 9, 82, 10]`:

```text title="Разбиения и слияния"
                [38 27 43 3 9 82 10]
           [38 27 43 3]        [9 82 10]
         [38 27]  [43 3]      [9 82]  [10]
        [38] [27] [43] [3]   [9] [82]
слить:  [27 38]   [3 43]     [9 82]
слить:     [3 27 38 43]      [9 10 82]
слить:         [3 9 10 27 38 43 82]
```

### Анализ MergeSort

Главное — слияние: для фрагмента `c[l..p]` оно требует не более p − l сравнений. Отсюда уравнение для числа сравнений в **худшем** случае:

- T(1) = 0,
- **T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + n − 1**.

Решение: **T(n) = n log₂ n + O(n)** (для n = 2ᵏ ровно n log₂ n − n + 1). Это **намного** лучше, чем n²/2 у алгоритмов из темы 5!

- **Недостаток:** нужна **дополнительная память O(n)** (вспомогательный массив для слияния) и много копирования.
- **Достоинство:** время n log n **всегда** (и в худшем случае), алгоритм **устойчив** (при равных ключах берём элемент из левой части — `<=`).
- Лекция упоминает интересную задачу: можно ли сливать **на месте**, без дополнительного массива? Она годами оставалась открытой — и была решена (положительно), но такие методы сложны.

## Рекуррентные уравнения — как их решать

Сложность рекурсивного алгоритма записывают **рекуррентным уравнением**. Вот три способа его решить.

### 1. Разворачивание (подстановка) {own}

:::own
«Разворачивание» — стандартная техника; на слайдах результат дан без выкладок, поэтому добавляю их для ясности.
:::

Для T(n) = 2T(n/2) + n − 1, n = 2ᵏ:

T(n) = 2T(n/2) + (n − 1)
 = 4T(n/4) + (n − 2) + (n − 1)
 = 8T(n/8) + (n − 4) + (n − 2) + (n − 1)
 = … = 2ᵏ·T(1) + k·n − (1 + 2 + … + 2ᵏ⁻¹)
 = 0 + n log₂ n − (n − 1).

### 2. Дерево рекурсии {own}

Нарисуйте дерево вызовов и в каждом узле запишите стоимость «собственной работы» (без вызовов). Для MergeSort: на каждом из **log₂ n** уровней суммарная стоимость слияний около **n**, значит всего около **n log₂ n**.

### 3. Основная теорема (о рекурсии)

Со слайдов 2009 — готовый рецепт для уравнений вида **T(n) = a·T(n/b) + f(n)** (a ≥ 1, b > 1):

:::def
Сравните f(n) с функцией **n^(log_b a)**:
1. если f(n) = O(n^(log_b a − ε)) для некоторого ε > 0 (f растёт **медленнее**), то **T(n) = Θ(n^(log_b a))**,
2. если f(n) = Θ(n^(log_b a)) (одинаково быстро), то **T(n) = Θ(n^(log_b a) · log n)**,
3. если f(n) = Ω(n^(log_b a + ε)) для некоторого ε > 0 (f растёт **быстрее**) и a·f(n/b) ≤ c·f(n) для константы c < 1, то **T(n) = Θ(f(n))**.
:::

:::analogy
Кто «побеждает»: работа, распределённая по листьям дерева рекурсии (n^(log_b a)), или работа при разбиении/объединении (f(n))? Если листья — случай 1; ничья — случай 2 (добавляется log n, потому что столько уровней); если объединение — случай 3.
:::

| Уравнение | n^(log_b a) | Случай | Результат | Пример |
|---|---|---|---|---|
| T(n) = 2T(n/2) + n | n | 2 | Θ(n log n) | MergeSort |
| T(n) = T(n/2) + 1 | 1 | 2 | Θ(log n) | бинарный поиск |
| T(n) = 2T(n/2) + 2 | n | 1 | Θ(n) | min-max |
| T(n) = 3T(n/2) + n | n^1,585 | 1 | Θ(n^(log₂ 3)) | Карацуба (тема 8) |
| T(n) = 2T(n/2) + n² | n | 3 | Θ(n²) | |

:::warn
Теорема **не охватывает** уравнения вида T(n) = T(n − 1) + n (разбиение «1 ; n−1») — там нет деления на b. Их решают разворачиванием: T(n) = n + (n−1) + … = Θ(n²).
:::

=== summary ===

## Рекурсия

- функция вызывает сама себя; **базовый случай** + **шаг, уменьшающий** задачу.
- у каждого вызова локальные копии переменных → **стек вызовов**; память = глубина рекурсии.

## Примеры

- **dwojkowy(x):** цифра x%2, сначала рекурсия для x/2, потом печать.
- **Ханой:** n−1 на вспомогательный, самое большое на цель, n−1 на цель; **H(n) = 2H(n−1) + 1 = 2ⁿ − 1**.
- **Перестановки:** n! результатов, время Θ(n!), память O(n).

## Разделяй и властвуй

малые данные → напрямую; большие → разделить, решить подзадачи, объединить.

## MergeSort

- разбиение пополам, рекурсия, **слияние** (≤ p + q − 1 сравнений).
- T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + n − 1 = **n log₂ n + O(n)** (и в худшем случае).
- память **O(n)**, **устойчив**.

## Основная теорема: T(n) = aT(n/b) + f(n)

| f(n) vs n^(log_b a) | T(n) |
|---|---|
| медленнее | Θ(n^(log_b a)) |
| так же | Θ(n^(log_b a) log n) |
| быстрее (+ условие регулярности) | Θ(f(n)) |

Не применяется к T(n) = T(n−1) + … — разворачиваем.

Решите (укажите порядок Θ):

a) T(n) = 4T(n/2) + n  b) T(n) = 4T(n/2) + n²  c) T(n) = 4T(n/2) + n³  d) T(n) = 8T(n/2) + n²  e) T(n) = T(n/3) + 1  f) T(n) = T(n − 1) + 1

Найдите n^(log_b a) и сравните с f(n). Осторожно с f) — это не вид a·T(n/b).
::solution
a) n^(log₂ 4) = n², f = n растёт медленнее → **Θ(n²)** (случай 1).
b) f = n² = n^(log₂ 4) → **Θ(n² log n)** (случай 2).
c) f = n³ растёт быстрее; 4·(n/2)³ = n³/2 ≤ ½·n³ → **Θ(n³)** (случай 3).
d) n^(log₂ 8) = n³, f = n² медленнее → **Θ(n³)**.
e) n^(log₃ 1) = n⁰ = 1, f = 1 → **Θ(log n)** (случай 2).
f) теорема не работает; разворачивая: T(n) = T(0) + n → **Θ(n)**.
:::

:::task level=2 source="own" title="Сколько сравнений при слиянии?"
Сливаем отсортированную последовательность длины p с отсортированной последовательностью длины q. Сколько сравнений сделает Scal **минимум** и **максимум**? Приведите примеры данных для p = q = 3.
::hint
Слияние заканчивается, когда одна из последовательностей исчерпана, — остаток другой переписывается без сравнений.
::solution
- **Минимум: min(p, q)** — когда все элементы короткой последовательности меньше всех элементов другой, например `[1, 2, 3]` + `[4, 5, 6]` → 3 сравнения.
- **Максимум: p + q − 1** — когда элементы «чередуются» и обе последовательности заканчиваются почти одновременно, например `[1, 3, 5]` + `[2, 4, 6]` → 5 сравнений.
:::

:::task level=3 source="own" title="Перестановки — сколько вызовов?"
Для процедуры `permutations(a, k)` с лекции (код на Java выше) посчитайте, сколько раз она будет вызвана для массива из 4 элементов (`permutations(a, 4)`) и сколько перестановок выведет. Найдите рекуррентную формулу для числа вызовов C(n).
::hint
Вызов с параметром k (k > 1) делает k вызовов с параметром k − 1. Вызов с k = 1 только печатает.
::solution
C(1) = 1, **C(n) = 1 + n · C(n − 1)**. Отсюда: C(2) = 3, C(3) = 10, **C(4) = 41** вызов, а выведенных перестановок **4! = 24**. Число вызовов — 1 + 4 + 4·3 + 4·3·2 = 41 (сумма по уровням дерева рекурсии).
:::
